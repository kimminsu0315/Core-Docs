## 0. 설계 원칙

이 문서에서 물류 작업 시스템을 이하 Core로 표기한다. 이 챕터는 Core 시스템 운영의 핵심 원칙을 정의한다. 본문의 예시에 나오는 라벨·수량·시간·공정 흐름은 설명용이다.

### 0.1 Core는 공정 내 Unit 이동 경로를 추적하는 시스템이다

Core의 실제 관리 범위는 물류 AMMR, WIP, CNC 작업대 간 Unit 이동으로 한정된다. 제품 생산 이력, 품질 추적, 작업 실적 등은 Core가 자동으로 추적하는 영역이 아니며 GM/SM 등 외부 시스템의 영역이다. 단, 작업 실적은 사용자가 작업 실적 화면에서 수동 입력하거나 CNC 공정 AMMR이 자율 보고로 올리면 Core가 기록한다.

**※ 이 원칙이 필요한 이유**

문서를 처음 보는 사람이 Unit ID, 공정 이력, GM 연동 등을 보고 제품 생산 관리 시스템으로 오해할 수 있다. Core가 관리하는 것은 어떤 Unit이 어느 공정 구간을 거쳤는지에 대한 이동 경로이며, 각 공정에서 어떤 작업이 이루어졌는지, 제품의 품질이나 실적은 어떠한지는 Core가 알지 못한다.

**※ 현재 한계가 생긴 배경**

사람과 협업하는 환경과 WIP이 없는 공정이 공존하는 환경상 Unit의 이동을 추적할 수 없는 한계가 있다. 공정 추적은 이동 자동화만으로 가능하나, 제품 추적은 작업 자동화 또는 실적 처리 자동화가 추가로 갖춰져야 한다. 이는 현재 Core의 범위 밖이다.

### 0.2 Core가 본 것만 기록한다

이 시스템의 가장 중요한 설계 원칙은 "Core가 직접 확인한 데이터만 기록한다"는 것이다. Slot 상태, AMMR Pickup·Dropoff 보고, QR Scan 등 Core가 실제로 감지한 정보만 기록하며, 감지하지 못한 구간은 이유와 무관하게 null로 처리한다.

**※ 이 원칙이 필요한 이유**

신뢰성: Core가 직접 확인한 데이터만 기록하면 잘못된 정보가 시스템에 쌓이지 않는다. 추정이나 간접 정보를 기록하다 보면 나중에 데이터 정합성 문제가 생긴다.

확장성: 나중에 Sensor나 장비가 추가되면 Core가 보는 범위가 늘어나고, 그때 자연스럽게 기록이 늘어나는 구조다.

유지보수: 원칙이 명확하면 나중에 다른 개발자나 담당자가 시스템을 이해할 때도 혼란이 없다.

**※ 적용 범위**

"Core가 본 것만 기록한다"는 원칙은 WIP을 거치지 않는 공정, 수동 처리 구간, 자동 추적 불가 공정 모두에 동일하게 적용된다. null은 오류가 아니라 Core가 해당 구간을 감지하지 못했음을 의미한다.

**※ Slot 상태와 Unit 식별값 확정 기준**

Slot 상태는 각 클라이언트(AMMR 태블릿·WIP 프로그램)가 Sensor와 보유 Unit 정보로 판정한 Slot 상태로 Core에 보고하며, Core는 이를 수신·기록한다. Slot에 적재된 Unit의 식별값을 확정하는 기준은 QR Scan이며, AMMR 이동 구간처럼 QR Scan이 불가능한 구간은 추정값으로 관리한다.

Unit 식별값은 출처에 따라 두 등급으로 운영된다 — **확정 등급**은 QR 인식·수동 입력 시점에 부여되며, **추정 등급**은 AMMR Pickup·Dropoff 동작 시점에 부여된다. 두 등급은 후속 운영에 동일 권위로 사용되며, 추정 등급 상태로도 정상 작업 진행이 가능하다. 추정값은 다른 QR Scan 시점에 실제값으로 보정된다. 다만 AMMR 태블릿을 거쳐 들어오는 적재 정보는 입력 수단과 무관하게 추정 등급이다.

WIP Slot과 AMMR 자체 Slot 모두 Slot Sensor와 Vision Sensor가 이중으로 감지한다. 단, AMMR의 Manipulator Vision Sensor는 QR 인식이 불가하므로 AMMR Slot Unit 식별값은 추정 등급으로 운영된다.

> **[예시] Core 원칙 적용 — 공정 기록 예시**
>
> 상황: 26SF03002001_001이 CNC → 세척 이동 중 현장 작업자가 WIP을 거치지 않고 직접 세척 구역으로 가져다 놓음.
>
> 공정 / 입고 시간 / 작업 시작 / 작업 종료 / 출고 시간 / 수량
>
> ─────────────────────────────────────────
>
> CNC 2공정 / 11:45 / 11:46 (CNC 공정 AMMR) / 13:20 (CNC 공정 AMMR) / 13:25 / 16개
>
> 세척 / null / null / null / null / null  ← (WIP 미경유)
>
> ─────────────────────────────────────────
>
> → null은 오류가 아니다. Core가 감지하지 못한 구간은 null로 표시하는 것이 정상이다.

### 0.3 안전망 요구

이 시스템은 다음 상황에서 해당 Slot 또는 작업의 신규 진행을 일시 차단하고, 원인이 해소되면 자동 해제할 수 있어야 한다.

- **외부 측 상태 미인지**: 외부 시스템 또는 AMMR과의 통신이 두절되어 외부 측 상태를 알 수 없는 동안 신규 작업을 강행하면, 통신이 끊긴 사이 외부에서 발생한 상태 변화를 반영하지 못해 잘못된 위치의 Pickup·Dropoff 등 사고가 발생할 수 있다. 통신이 끊긴 영역의 신규 작업은 자동 차단한다.
- **물리적 안전**: AMMR HW가 장애를 보고했거나 도착 시점에 목적지가 만재이거나 물리 충돌 상황이 감지된 경우, 추가 작업을 강행하면 사고 위험이 있다. 해당 영역의 신규 작업은 자동 차단한다.
- **데이터 정합성 보호**: Slot 상태와 Unit 식별값이 일치하지 않는 Slot은 추정으로 임의 채우지 않고 사용 보류한다. Unit이 갈 수 없는 공정이나 수행할 수 없는 작업으로 들어온 경우 등 Core가 유효하지 않다고 판정하는 상황도 해당 Slot 또는 작업을 사용 보류한다.
- **운영자 인지**: 모든 보류 상태는 그 사유와 함께 Core Dashboard에 표시하여 운영자가 확인할 수 있어야 한다.
- **자동 해제**: 원인이 해소되면 별도 사용자 명령 없이 자동으로 해제된다. 원인이 저절로 사라지지 않는 경우에는 운영자가 원인을 해소하는 조치를 수행하며, 조치로 원인이 사라지면 해제도 자동으로 이루어진다.

이 요구는 운영 데이터 신뢰성과 물리 자산(WIP·CNC 작업대·AMMR·Unit) 안전을 위한 시스템 차원 안전망이다.

### 0.4 Slot 상태 보고

Slot의 현재 상태는 각 클라이언트(AMMR 태블릿·WIP 프로그램)가 자기 Sensor와 보유 Unit 정보로 판정해 Core에 보고한다. 클라이언트는 상태가 전이한 시점에 해당 Slot을 보고하고, 초기 연결 시점에는 전체 Slot 상태와 Slot별 Unit 식별값을 함께 전달한다. 그 밖의 전체 보고 시점은 클라이언트별로 정의된다. 보고에 대해 정정 응답이 돌아오면 클라이언트는 그 값을 자기 상태에 반영한다. Unit이 갈 수 없는 공정인지, 수행할 수 없는 작업인지는 클라이언트가 판정하지 않으며 Core가 판정한다. Core는 확정한 Unit 정보를 응답에 돌려주며, 판정 결과를 반영하는 형태는 클라이언트별로 다르다 — 공정 설비(WIP 프로그램)에는 그 Unit을 이 설비 공정에서 쓸 수 있는지(사용 가능 여부)와 그 Slot이 사용 보류가 된 사실·사유를 함께 회신하고, Unit을 운반하는 물류 AMMR에는 목적지 Job 배정 정정으로 반영한다.

| 상태      | 적용           | 의미                                                                           |
|-----------|----------------|--------------------------------------------------------------------------------|
| 정상 점유 | 공통           | Unit이 있고 식별됨                                                             |
| 비어 있음 | 공통           | 미점유                                                                         |
| 사용 보류 | 공통           | 식별 안 되는 점유·정합 이상 등                                                 |
| 작업 실패 | 물류 AMMR 전용 | Job 실패로 인한 이상 상태                                                      |
| Pair 대기 | CNC WIP 전용   | 되담기 진행 중·출고 미완 대기 (짝 Tray 미도착·부분 진행 되담기 임시 배치 포함) |

사용 보류·작업 실패·Pair 대기는 정상 점유·비어 있음 밖의 특수 상태이며, Core Dashboard와 각 클라이언트 UI에 표시된다.

작업 실패는 실물 상태가 다시 서면 벗어난다 — 점유가 끊기면 비어 있음으로 돌아가고, 점유가 남아 있으면 담당자가 태블릿에서 식별값을 채워 다시 보고할 때 정상 점유로 돌아간다. 채우기 전까지는 식별 안 되는 점유라 사용 보류로 다룬다.

## 1. 공장 및 시스템 개요

이 챕터는 공장 시설과 Core 시스템 구성요소를 정의한다. 금속 가공품을 생산하는 메탈 가공 공장의 사내 물류를 자동화하는 시스템이며, 모든 WIP과 AMMR은 사내 내부망으로 연결된다.

**※ 모든 Slot(WIP·AMMR·CNC 작업대)은 1 Unit만 담는다.**

**※ 일반 공정 WIP·CNC WIP은 통합 Slot으로 운영하며, 입고·출고 구분은 QR Scan 시 함께 전달되는 구분값으로 판정한다. CNC 작업대는 SM 측 입고/출고 Slot Sensor 신호를 사용한다.**

### 1.1 시스템 구성요소

**※ 로봇 / 장비 / 외부 시스템**

| 이름                       | 역할 |
|----------------------------|---|
| GM 시스템 (외부)           | 제품 정보 / Recipe 제공 (REST API, Endpoint 등 **변동 가능**). 매 응답에 조회 조건에 맞는 오더를 전부 싣는다. |
| SM 시스템 (외부)           | 공정-CNC 작업대 Mapping 정보, CNC 작업대 입고/출고 Slot Sensor 신호(On/Off), 장비 상태(대기·작업 중·예열·통신 끊김) 제공. 매 응답에 전 설비를 싣는다.<br><br>Core가 직접 REST API 폴링하여 수신 (Endpoint 등 **변동 가능**). |
| Core                       | 이 시스템 메인 서버. 모든 WIP·CNC 작업대·물류 AMMR 간 Unit 이동을 추적·관리하고, 외부 시스템(GM/SM) 연동·물류 AMMR 명령·WIP 프로그램 통신·Core Dashboard 인터페이스·독립 프로그램 연동을 담당한다. |
| CNC WIP의 이동 로봇        | CNC WIP 내부에서 통합 Slot ↔ 스테이션 간 Unit 이동 담당 (1회 1 Unit).<br><br>CNC WIP 프로그램 제어 하에 Slot Sensor 감지 시 해당 위치로 이동하여 QR 인식 담당. Vision Sensor로 QR을 인식한다. |
| CNC WIP의 되담기 작업 로봇 | 스테이션에서 공정 Tray의 제품을 적층 Tray로 옮기는 실제 되담기 작업 수행. Vision Sensor로 적층 Tray의 제품 유무를 감지한다. |
| 물류 AMMR                  | 공정 구간 간 Unit 외부 이동 (최대 6 Unit 적재). 현재 2대 운영.<br><br>※ AMMR이 현재 적재 중인 Unit 목록은 추정값이다. Pickup 동작 시 출발 Slot의 QR Scan 정보를 기반으로 추정되며, 후속 QR Scan 시점에 실제값으로 확정된다.<br><br>※ AMMR 자체 Slot 점유는 Slot Sensor와 Manipulator Vision Sensor가 이중으로 감지한다. 단, Manipulator Vision Sensor는 QR 인식이 불가하므로 Unit 식별값 갱신은 별도 QR Scan 시점까지 추정 등급으로 운영된다. |
| 충전 스테이션              | 물류 AMMR이 충전 시 도킹하는 물리 위치. 도킹·충전·이탈 등 물리적 수행 세부와 자체 임계에 따른 충전 중단 결정은 AMMR HW가 자체 처리한다. Core는 Charge Job 수행 결과 보고만 수신하며 충전 스테이션과 직접 통신하지 않는다. |
| CNC 공정 AMMR              | CNC 공정 작업 수행. 작업 시작·종료 보고는 별도 강제 사항이 아니며, 보고할 경우 QR Scan으로 보고한다. 총 4대 운영.<br><br>단, CNC 공정 AMMR이 없는 라인은 사람이 수동 처리. |

**※ WIP (Work In Process)**

| 이름                      | 역할 |
|---------------------------|---|
| 일반 공정 WIP (통합 Slot) | 공정의 Unit 대기 Slot. 각 Slot은 Slot Sensor와 Vision Sensor가 점유를 이중 감지하며, 입고·출고는 QR Scan 구분값으로 판정 |
| CNC WIP (통합 Slot)       | 각 Slot은 Slot Sensor와 Vision Sensor가 점유를 이중 감지한다.<br><br>통합 Slot에 공정 Tray Unit·적층 Tray Unit이 함께 놓여 Pair가 갖춰지면 스테이션으로 이동 → 되담기 수행<br><br>완료된 적층 Tray Unit은 통합 Slot에 남아 물류 AMMR이 다음 공정으로 이동시킨다. 빈 공정 Tray Unit도 통합 Slot에 남으며, 물류 AMMR이 회수 자리인 세척·블라스팅 WIP으로 옮겨 두면 물류 담당자가 거기서 회수한다.<br><br>입고·출고는 QR Scan 구분값으로 판정.<br><br>되담기 허브 역할 + 출고 후 다음 공정 이동 (일반 공정 WIP 구조적 겸행). |
| CNC 작업대 (입고/출고)    | 장비별 입고 1 Slot / 출고 1 Slot. 각 Slot Sensor 신호는 SM 시스템 폴링으로 수신하며, 두 신호의 조합이 CNC 작업대 점유 상태를 나타낸다. 작업 시작·종료는 외부 QR 보고가 있을 때만 기록된다.<br><br>(CNC 공정 AMMR 없는 라인은 사람이 수동 처리) |

**※ 통합 Slot WIP 구성**

선반 1대는 가로 3칸 × 6층 18 Slot이며, 선반마다 001부터 번호가 붙는다. 선반 1대가 통합 Slot WIP 하나이고, 같은 공정의 선반 여러 대가 모여 그 공정을 이룬다. 아래 표의 Slot 수는 그 공정 전체 합계다. CNC WIP 선반 가운데 하나는 예비 선반이다. 되담기를 하지 않고, Unit을 임시로 놓는 자리로 쓴다. 예비 선반도 같은 공정 코드를 쓰며, 어느 선반이 예비인지는 설치 시점에 정해져 운영 중 바뀌지 않는다.

| 공정          | 선반 수 | Slot 수 |
|---------------|---------|---------|
| CNC WIP       | 4       | 72      |
| DP            | 2       | 36      |
| 세척·블라스팅 | 4       | 72      |

**※ 설비 위치 기준 Marker**

물류 AMMR이 Pickup·Dropoff 위치를 정확히 잡도록 설비에 위치 기준 Marker를 부착한다. 통합 Slot WIP은 열마다 그 열 가장 위에 하나를 두어 그 열 6 Slot의 기준으로 삼고, CNC 작업대는 한 대마다 하나를 두어 그 CNC 작업대 위치의 기준으로 삼는다. AMMR은 목적지 Slot이 속한 열 또는 CNC 작업대의 Marker를 읽어 자기 위치를 맞춘 뒤 동작한다. Marker를 읽는 수단과 위치를 맞추는 방식은 AMMR HW 영역이다.

**※ CNC WIP 동작 Interlock**

CNC WIP은 내부에 이동 로봇과 되담기 작업 로봇을 두므로, 물류 AMMR이 이 설비에서 Pickup·Dropoff를 수행할 때 내부 로봇과 동작이 겹치면 안 된다. 물류 AMMR과 CNC WIP은 서로 동작이 겹치지 않도록 Interlock 신호를 직접 주고받으며, 이 신호는 Core를 거치지 않는다. 신호 방식과 배선은 설비·AMMR 양측 HW 영역이다.

**※ 사람**

| 이름            | 역할 |
|-----------------|---|
| 물류 담당자     | 외주 복귀 Unit 수령 및 재편 / 신규 Unit 구성 등록 및 Tray QR 스티커 부착 / 외주 배차 확정 및 출고 서류 처리 / 공정 Tray Unit 구성 분류 및 적층 Tray 제품 정보 매핑 후 CNC WIP에 전달 / 회수 자리인 세척·블라스팅 WIP에서 빈 공정 Tray Unit 회수 |
| 생산관리 담당자 | 시스템 전역 설정 변경 |
| 현장 작업자     | AMMR 장애 시 Unit 수동 이동 및 QR Scan / Recipe에 'Tray 되담기' 공정이 있는 Unit을 AMMR 대신 CNC WIP에 배치하거나 되담기를 직접 처리 (수동 되담기) |

이 표는 물류 운영에서 사람이 맡는 역할이며, Core Dashboard 계정 등급과는 별개 층이다. 본문에서 AMMR 태블릿 조작 주체로 쓰는 담당자는 이 표의 특정 역할이 아니라 그 시점에 태블릿을 다루는 사람을 가리키는 총칭이다.

**※ 비고: WIP에 이미 입고된 Unit의 이동 배치(교체 작업 등)는 이 시스템에서 제외한다. 교체가 필요한 경우 사람이 직접 처리한다.**

### 1.2 식별자 명명 규칙

이 절은 위치·설비·AMMR·Slot 식별자의 형식을 정의한다. 모든 산출물은 이 형식을 따른다. 통합 Slot WIP 식별자는 Core가 정의하며(GM·SM 미제공), CNC 작업대 식별자는 SM 데이터(장비명·입출고 신호)에서 파생한다. AMMR 식별자 값은 설치 시점에 Core가 할당하고, 설비 ID·Slot ID 전체 목록도 설치 시점에 Core가 제공한다.

**※ 위치 ID**

| 대상                 | 형식                       | 예                   |
|----------------------|----------------------------|----------------------|
| 통합 Slot WIP        | `WIP-{공정코드}{일련번호}` | `WIP-CLN001`         |
| 통합 Slot WIP의 Slot | `{WIP ID}-{열}{행}`        | `WIP-CLN001-A1`      |
| CNC 작업대           | `CNC-{MACHINE_NAME}`       | `CNC-RAC-A01`        |
| CNC 작업대의 Slot    | `{CNC 작업대 ID}-{구분}`   | `CNC-RAC-A01-BEFORE` |

- 일련번호 = 3자리 0채움(`001`~`999`)
- Slot 열 = `A`~`ZZ`, 행 = `1`~`999`(0채움 없음)
- CNC 장비명 = SM 장비명 값(예 `RAC-A01`), 구분 = `BEFORE`(입고) / `AFTER`(출고)
- CNC 작업대는 WIP이 아니므로 `WIP-` 접두를 쓰지 않는다.
- CNC 작업대 ID는 SM이 제공하는 장비명을 그대로 이어받으므로, 분류 코드와 일련번호를 붙여 쓰는 이 규칙의 예외다.
- 위치 ID는 설비와 그 설비의 Slot 두 층위로 나뉜다. 통합 Slot WIP과 CNC 작업대 모두 설비 ID를 앞에 두고 뒤에 Slot 구분을 붙이는 같은 구조다. 물류 AMMR이 이동하는 목적지는 설비 ID로 지정하고, Unit을 싣거나 내리는 대상은 Slot ID로 지정한다.

**※ 공정 코드** (통합 Slot WIP)

| 공정                 | 코드 | 설비 ID 예   |
|----------------------|------|--------------|
| 세척·블라스팅        | CLN  | `WIP-CLN001` |
| DP(드라이 폴리싱)    | DP   | `WIP-DP001`  |
| CNC WIP(되담기 허브) | CNC  | `WIP-CNC001` |

세척·블라스팅은 같은 물리 통합 Slot WIP을 공유하므로 한 코드(CLN)로 둔다.

**※ AMMR ID**

| 대상             | 형식                    | 예                |
|------------------|-------------------------|-------------------|
| AMMR             | `AMMR-{타입}{일련번호}` | `AMMR-LOGI001`    |
| 물류 AMMR의 Slot | `{AMMR ID}-{열}{행}`    | `AMMR-LOGI001-A1` |

- 타입 = `LOGI`(물류용) / `PROC`(공정용). 공정용 AMMR은 Slot이 없다.
- 일련번호 = 3자리 0채움(`001`~`999`)
- 물류 AMMR Slot = 열 `A` 고정, 행 `1`~`6`.

## 3. Unit / Tray / 제품 구성

이 챕터는 제품·Tray·Unit의 구성 단위와 ID 정책을 정의한다.

### 3.1 구성 단위

**※ 구성 단위별 정의**

| 단위        | 구성                | 비고 |
|-------------|---------------------|---|
| 제품 (Item) | 금속 가공품 1개     | GM 시스템의 수량 단위 |
| Tray        | 제품 4개 안착       | 뚜껑 역할 Tray는 제품 없음 |
| Unit        | Tray N개 (최대 5단) | 최소 2단(뚜껑 1개 + 제품 Tray 최소 1단) ~ 최대 5단(뚜껑 1개 + 제품 Tray 4단). 최대 제품 16개. 수량에 따라 가변 구성 |

**※ 용어 보강**

"제품(Item)"은 개별 가공품을 가리킨다. "제품 정보"는 GM에서 받아오는 Metadata 묶음(모델·버전·부품명·수량·완료목표일·용도·Recipe 등)을 의미한다. 제품은 모델과 버전 조합으로 가르며, 이 조합이 SM에서 오는 공정-CNC 작업대 Mapping의 제품 축과 맞물린다. 같은 조합을 쓰는 오더가 여럿 있을 수 있다. 두 시스템은 같은 제품을 같은 표기로 내려준다. 표기가 갈리면 그 제품은 어느 CNC 작업대와도 맞물리지 않아 공정 미배정과 같이 이전 공정에서 대기한다.

예시: GM 100개 등록 → 5단 Unit 6개(96개) + 2단 Unit 1개(4개) = 총 7개 Unit

### 3.2 Tray 종류

**※ Tray 종류별 특성**

| 구분      | 이름      | QR 방식                    | 비고                                                                |
|-----------|-----------|----------------------------|---------------------------------------------------------------------|
| 되담기 전 | 공정 Tray | QR 스티커 (QR + 제품 목록) | 사람이 육안으로 제품 확인 가능                                      |
| 되담기 후 | 적층 Tray | QR 각인만                  | 스티커 없음. QR로만 식별. 필요 시 QR 발행 화면에서 식별 스티커 출력 |

물류 AMMR은 Tray 종류에 따라 Unit을 집고 놓는 방식이 갈릴 수 있다. 이송 지시를 받을 때 그 Unit의 Tray 종류를 함께 받는다.

**※ 공정 Tray Unit 구성**

| 단계 | 처리                                                                         |
|------|------------------------------------------------------------------------------|
| 1    | GM에서 신규 투입코드 수신 → QR 발행 화면에서 실제 입고 수량 확인             |
| 2    | 실제 입고된 수량 기준으로 공정 Tray Unit 구성 (수량 입력 → 시스템 제안 확인) |
| 3    | QR 스티커 출력 → 실물 공정 Tray에 부착                                       |
| 4    | 공정 투입 시작                                                               |

**※ 적층 Tray Unit 구성**

| 단계 | 처리                                                                |
|------|---------------------------------------------------------------------|
| 1    | 발주처에서 적층 Tray 납품 → 물류실 적치                             |
| 2    | 물류 담당자가 적층 Tray를 한 단씩 각인 QR로 Scan해 제품 정보를 매핑 |
| 3    | 적층 Tray를 임의 단수로 CNC WIP에 투입                              |
| 4    | CNC WIP이 짝 공정 Tray Unit에 맞춰 적층 Tray Unit 구성을 완성       |

### 3.3 Tray 되담기 규칙

**※ Tray 되담기란?**

공정 Tray에 담긴 제품을 적층 Tray로 옮기는 공정이다. Recipe에 명시된 필수 공정으로, 선택적으로 수행하는 것이 아니다. 공정 Tray는 QR 스티커가 붙어있어 사람이 내용물을 육안으로 확인할 수 있다. 반면 적층 Tray는 QR 각인만 있어 사람이 내용물을 직접 식별할 수 없으며, 시스템(Core Dashboard)을 통해서만 확인 가능하다.

> **[예시] 되담기 전/후 비교**
>
> 되담기 전 (공정 Tray): Tray에 제품 4개씩 안착, QR 스티커로 내용물 확인 가능.
>
> 되담기 후 (적층 Tray): 제품이 적층 Tray에 옮겨짐. QR 각인으로만 식별 (스티커 없음).

되담기는 CNC WIP 전용 로봇이 담당한다. 단, 현장 작업자가 직접 수동 되담기를 처리한 경우, 작업 실적 화면에서 되담기 완료를 등록한다. 이때 되담기 완료 사실과 어느 Tray에 무엇을 담았는지의 구성 리스트, 빈 공정 Tray Unit 식별값 리스트를 올리며, 되담은 Tray를 어디에 두었는지는 등록에 넣지 않는다. 되담은 적층 Tray는 다음 공정으로, 빈 공정 Tray Unit은 회수 자리인 세척·블라스팅 WIP으로 옮긴다. 통합 Slot에 그대로 두면 물류 AMMR이 옮기고, 담당자가 직접 옮기거나 빈 공정 Tray Unit을 그 자리에서 회수하기도 한다. 이는 CNC WIP 프로그램이 되담기를 마치고 올리는 내용과 같되, 놓인 자리는 그 프로그램의 QR Scan이 알린다.

되담기는 Recipe에 'Tray 되담기' 공정으로 명시적으로 삽입되어 관리한다. 이 공정은 GM이 선제적으로 판단해 Recipe에 포함해 전달하며, Core·담당자는 별도로 추가하지 않는다.

물류 AMMR이 CNC WIP에 Unit을 넣는 경우는 다섯이다 — Recipe에 'Tray 되담기' 공정이 명시된 경우, CNC 가공 결과 Unit이 다음 목적지 WIP 만재로 임시 보관을 배정받은 경우, CNC 가공 결과 Unit이 다음 공정에 받을 설비가 없거나 쓸 수 없어 설비가 설 때까지 둘 자리를 배정받은 경우, CNC 작업대에서 나온 Unit의 다음 공정이 자동 추적 대상이 아니어서 담당자가 가져가야 하는 경우, 물류 AMMR에 실린 Unit이 갈 곳을 잃어 임시 보관이 필요한 경우다.

되담기 공정이 명시되지 않은 Unit이 CNC WIP에 투입된 경우 정합성 이상 처리.

### 3.4 Unit ID 정책

**※ Unit 식별값 — Unit ID·라벨·Tray ID**

Unit은 여러 Tray로 구성되며, 식별은 세 층위로 나뉜다.
- **Unit ID** — Unit마다 유니크한 시스템 권위 식별값(UUID)이다. Core가 Unit 구성 시점에 부여하고 관리하며, 외부에 적재 정보를 회신할 때 이 값을 내려준다. 실물에는 인쇄되지 않는다.
- **라벨** (`투입코드_유닛번호` 형식, 예: `26SF03002001_001`) — 어떤 투입코드의 몇 번 Unit인지, 즉 제품 정보 수준의 정보를 담는 사람 읽기용 표기다. 공정 Tray 스티커에 인쇄된다.
- **Tray ID** — Tray마다 유니크한 시스템 권위 식별값(UUID)으로, 공정 Tray는 스티커 QR·적층 Tray는 각인 QR에 인코딩된다. 실물 Tray 수준의 유니크 식별자로, QR Scan·수동 입력 시점에 Core가 받는다.

Core가 현장에서 받는 값은 Tray ID이고, Core는 그 Tray가 어느 Unit에 속하는지를 조회해 Unit을 판정한다. 한 Unit의 어느 Tray ID로도 같은 Unit이 풀린다. 판정 결과인 Unit ID는 적재 정보 회신으로 외부에 돌려주며, 확정 등급 Unit 식별값은 이 판정을 기준으로 한다.

**※ Unit ID 관리 시점별 처리**

| 시점             | 처리 |
|------------------|---|
| 최초 사내 입고   | 담당자가 실제 입고 수량 기준으로 QR 발행 화면에서 Unit 구성 → QR 스티커 출력 → 실물 부착 |
| 외주 복귀 시     | 이전 Unit ID 완전 폐기 → 실제 복귀 수량 기준으로 신규 Unit 구성 → 새 Unit ID 부여 (새 QR 부착) |
| 적층 Tray 되담기 | 각 Tray를 각인 QR로 식별. 물류 담당자가 제품 정보를 매핑하고, CNC WIP이 짝 공정 Tray Unit에 맞춰 Unit 구성을 완성 |
| 이력 추적        | Unit 단위로만 추적. 외주 구간은 외주 배치 단위로 연결 |

> **[예시] Unit 구성 흐름 — 제품 100개 중 20개가 먼저 입고된 경우**
>
> 상황: 투입코드에 제품 100개 등록. 1차로 20개가 먼저 사내에 입고됨.
>
> [1차 입고 - 20개]
>
> ① 담당자가 QR 발행 화면에서 Unit 구성 수량 "20" 입력
>
> ② 시스템이 Unit 구성 제안: 5단 Unit 1개(16개) + 2단 Unit 1개(4개) = 총 2개 Unit
>
> ③ 담당자 확인 후 QR 발행 → 26SF03002001_001, 26SF03002001_002 생성 → 실물에 스티커 부착
>
> ④ 공정 투입 시작
>
> [2차 입고 - 80개]
>
> ① 담당자가 QR 발행 화면에서 수량 "80" 입력
>
> ② 시스템 제안: 5단 Unit 5개(80개) = 총 5개 Unit → QR 발행 → 26SF03002001_003~26SF03002001_007 생성
>
> → 투입코드의 제품 전체(100개)에 대해 미리 Unit을 만들지 않고, 실제 입고된 수량 기준으로만 Unit을 구성한다.
>
> **[예시] 외주 복귀 후 Unit 구성 — 복귀 수량이 달라진 경우**
>
> 상황: 26SF03002001_001(16개), 26SF03002001_002(4개) 총 20개가 외주로 나갔다가, 복귀 시 18개만 돌아온 경우.
>
> ① 담당자가 외주 관리 화면에서 복귀 수량 "18" 입력
>
> ② 시스템 제안: 5단 Unit 1개(16개) + 2단 Unit 1개(2개) = 총 2개 Unit
>
> ③ 기존 26SF03002001_001, 26SF03002001_002 폐기 → 신규 26SF03002001_008, 26SF03002001_009 생성
>
> ④ 외주 배치 이력에 출발 수량 20 / 복귀 수량 18 기록
>
> → 수량 불일치(20개 출발, 18개 복귀)가 발생해도 시스템은 있는 그대로 기록한다.

## 4. 공정 전체 목록

이 챕터는 Core가 자동으로 추적하는 공정을 열거하고, 그 밖의 공정을 어떻게 다루는지 정의한다. 공정 순서는 제품 Recipe마다 다르며 GM 시스템에서 수신한다.

**※ 공정 분류 (Core 자동 추적 가능 여부)**

| 분류                | 공정 목록                            | 설명 |
|---------------------|--------------------------------------|---|
| Core 자동 추적 가능 | CNC, DP, 세척, Blasting, Tray 되담기 | 입출고 QR Scan으로 기록 가능. Core가 직접 감지. CNC는 CNC 작업대별 공정 배정에 따라 N개 공정. Tray 되담기는 CNC WIP에서 수행. |
| Core 자동 추적 불가 | 물류, 사출, Laser, PQC, 측정         | Recipe에는 존재하지만 Core가 자동으로 추적하지 않음. 시간 기록은 기본 null이며, 사용자 수동 입력 시 기록 가능. 공정 목록 칸은 대표 예시이며, 열거 밖 공정명도 같게 다룬다. |

열거에 없는 공정명이 Recipe로 들어오면 자동 추적 불가로 다룬다. 외부 공정명은 오더마다 새로 생길 수 있어 Core가 전부 열거하지 않는다. 공정명 대조는 열거한 공정명으로 시작하는지를 본다. 실물 Recipe는 같은 공정이 회차를 달고 여러 번 나온다(예: 세척#1·세척#3). 공정 분류는 공정명으로 가르되, 같은 공정명이라도 Recipe 항목의 가공처가 사내가 아니면 Core 자동 추적 대상이 아니다. 사외 가공처 공정은 외주 흐름으로 다루며 Core는 그 구간을 추적하지 않는다. 사내 가공처 목록은 시스템 설정으로 관리하며, 이 목록에 있는 값만 사내로 보고 나머지 가공처는 모두 사외로 다룬다. 같은 사업장이라도 표기가 다른 값이 들어오면 그 표기마다 목록에 등재한다. CNC 공정은 번호형 배정값(CNC 뒤에 공백을 두고 번호가 붙는 형식·예: CNC 3·CNC 6-1)만 대조 대상이며, 번호형이 아닌 배정값의 CNC 작업대는 자동 배정 대상이 아니다. Recipe 공정과 CNC 작업대 배정값의 대조는 값이 정확히 같은지를 본다. 앞부분만 같은 값은 다른 공정이다(예: CNC 3과 CNC 3-1).

**※ 전체 공정 목록**

| 공정명        | WIP 형태                            | 담당                                                                | 비고 |
|---------------|-------------------------------------|---------------------------------------------------------------------|---|
| 물류          | 없음                                | 사람 (물류 담당자)                                                  | Core 자동 추적 불가. 외주 배차 및 복귀는 담당자가 외주 관리 화면에서 처리. |
| 사출          | 없음                                | 사람                                                                | Core 자동 추적 불가. |
| CNC           | 장비별 CNC 작업대 (입고 1 / 출고 1) | CNC 공정 AMMR + 물류 AMMR<br><br>(CNC 공정 AMMR 없는 라인은 사람)   | CNC 작업대별 공정 배정에 따라 N개 공정. CNC 공정 AMMR 유무에 따라 작업 감지 방식 다름. |
| DP            | 통합 Slot WIP                       | 물류 AMMR + 사람                                                    | 공정 자동화 없음. WIP QR Scan으로 처리. 작업 자체는 사람이 수행. |
| Laser         | 없음                                | 사람                                                                | Core 자동 추적 불가. |
| 세척·블라스팅 | 통합 Slot WIP                       | 물류 AMMR + 사람                                                    | 공정 자동화 없음. WIP QR Scan으로 처리. 작업 자체는 사람이 수행. |
| PQC           | 없음                                | 사람                                                                | Core 자동 추적 불가. |
| 측정          | 없음                                | 사람                                                                | Core 자동 추적 불가. |
| Tray 되담기   | 통합 Slot WIP                       | CNC WIP의 이동 로봇 + CNC WIP의 되담기 작업 로봇 + 물류 AMMR + 사람 | CNC WIP에서 수행하는 되담기 허브. 이동 로봇과 되담기 작업 로봇 2대가 CNC WIP 프로그램을 통해 순차 작업. |

### 4.1 CNC 작업대 동작 방식

Core 입장에서 CNC 작업대 동작 방식은 CNC 공정 AMMR 유무와 무관하게 동일하다. AMMR이 없는 라인은 사람이 수동으로 작업을 수행한다.

**※ CNC 작업대 항목별 정의**

- **CNC 작업대 구성**: 장비별 입고 1 Slot / 출고 1 Slot. 한 번에 한 Unit만 다루며, 입고·출고 두 Slot이 모두 빈 CNC 작업대에만 다음 Unit이 들어가고, 입고가 비고 출고에만 Unit이 남은 CNC 작업대에서 그 Unit을 회수한다
- **입고·출고 감지**: SM 폴링 → 입고 Slot Sensor On = 입고, 출고 Slot Sensor On = 출고. 두 신호 조합이 CNC 작업대 점유 상태(비어 있음·작업 대기·작업 중·출고 대기)를 나타낸다
- **작업 시작·종료 기록**: 외부 QR Scan으로 보고 시 기록 (보고 없으면 미기록)
- **Unit 확정**: QR Scan 시점에 확정
- **공정 배정**: CNC 작업대마다 담당하는 제품(모델·버전)과 공정을 SM 시스템에서 수신
- **장비 상태**: 대기·작업 중·예열·통신 끊김을 SM 시스템에서 수신. 열거에 없는 값이 들어오면 사용 불가로 다룬다
- **공정 미배정·장비 사용 불가 시**: 이전 공정 자리에서 대기 → 배정되고 사용 가능해지는 시점에 이동. 이전 공정이 CNC 작업대여서 CNC 작업대를 비워야 하면 CNC WIP에 임시 보관한다
- **CNC 작업대 우선순위**: 시스템 설정값으로 관리. 같은 제품·공정을 담당하는 CNC 작업대가 여럿이면 우선순위가 높은 쪽으로 먼저 배정

> **[예시] CNC 1공정 (QR 보고 없음) vs CNC 2공정 (QR 보고 있는 경우) 기록 비교**
>
> ▶ CNC 1공정 (QR 보고 없음):
>
> CNC 작업대 입고: 10:05 (Slot Sensor) / 작업 시작: null / 작업 종료: null / CNC 작업대 출고: 11:30 (Slot Sensor)
>
> ▶ CNC 2공정 (작업 시작·종료 QR 보고 있는 경우):
>
> CNC 작업대 입고: 11:45 (Slot Sensor) / 작업 시작: 11:46 (QR Scan) / 작업 종료: 13:20 (QR Scan) / CNC 작업대 출고: 13:25 (Slot Sensor)
>
> → 두 경우 모두 CNC 작업대 입고·출고 시각은 각 Slot Sensor가 On으로 바뀐 것이 확인된 시점이다. 외부 시스템은 신호의 현재 상태만 제공하고 신호가 바뀐 시각은 따로 내려주지 않는다. 작업 시작·종료는 외부 QR 보고가 있을 때만 기록되며, 보고는 외부 측 자율로 강제 사항이 아니다.

**※ CNC 작업대 구성**

SM은 설비 57대(RAC-A01~A57) 데이터를 제공하나 물류 AMMR 자동화 대상은 30대이며, 대상 설비 목록은 시스템 설정값으로 관리한다. 장비 1대는 입고 1 Slot·출고 1 Slot을 가져 자동화 대상 30대는 60 Slot이다. 어느 장비가 어느 공정을 담당하는지는 장비마다 따로 정해진다. Unit이 거치는 CNC 작업대는 Recipe가 정한 공정 순서를 따르며, 사내 CNC 공정이 없는 Recipe면 이 CNC 작업대를 거치지 않는다.

## 6. CNC WIP 동작 로직

이 챕터는 CNC WIP 프로그램이 수행하는 입고 판단 케이스와 출고 Trigger를 정의한다.

### 6.1 입고 판단 케이스

**※ 입고 판단 케이스별 처리**

CNC WIP 프로그램은 Core 회신 Unit 정보(Tray 형태 포함)와 자기 Slot Sensor·Slot 상태 판정을 결합해 Pair 판단을 자체 수행한다. 적층 Tray는 제품 정보가 매핑된 상태로 들어오며, CNC WIP이 제품 정보로 짝 공정 Tray Unit을 식별해 적층 Tray Unit 구성을 완성한 뒤 Pair 판단·되담기를 진행한다.

**Case 1** — 공정 Tray 입고 / 현재 Slot 상태: 적층 Tray 없음 (Pair 미완성)
- 처리: 되담기 불가 → Slot에서 Pair 대기. Pair가 갖춰질 때까지 해당 Slot 유지, 새 입고 작업 미생성.

**Case 2** — 공정 Tray 입고 / 현재 Slot 상태: 적층 Tray 있음 (Pair 완성)
- 처리: 되담기 진행 → 완료 후 출고 처리.

**Case 3** — 적층 Tray 입고 / 현재 Slot 상태: 공정 Tray 없음 (Pair 미완성)
- 처리: 되담기 불가 → Slot에서 Pair 대기. Pair가 갖춰질 때까지 해당 Slot 유지, 새 입고 작업 미생성.

**Case 4** — 적층 Tray 입고 / 현재 Slot 상태: 공정 Tray 있음 (Pair 완성)
- 처리: 되담기 진행 → 완료 후 출고 처리.

**※ 적층 Tray는 임의 단수로 투입되므로 CNC WIP에 올라오는 단수·구성은 사전에 확정되지 않는다. 되담기가 부분 진행된 상태로 통합 Slot에 임시 배치될 수 있으며, 이 진행 중·부분 배치 상태는 Pair 대기로 보고한다. 출고 처리는 되담기 완료 시점에만 수행한다.**

> **[예시] Slot Pair 대기 및 이동 로봇 대기 상황**
>
> 상황: 공정 Tray 26SF03002001_001이 CNC WIP 통합 Slot에 들어왔는데, 아직 적층 Tray가 없는 상태 (Case 1)
>
> ① 26SF03002001_001 공정 Tray 입고 → CNC WIP 프로그램이 "적층 Tray 없음" 확인 → Case 1 판정
>
> ② Slot은 26SF03002001_001이 점유한 채로 대기 상태 유지
>
> ③ 이동 로봇은 적층 Tray가 들어올 때까지 대기
>
> ④ 적층 Tray 입고 → Pair 완성 → 이동 로봇이 스테이션으로 이동 → 되담기 진행
>
> Slot이 꽉 찬 상태에서 새 Unit이 들어오려 할 때:
>
> → 이동 로봇이 Vision Sensor로 통합 Slot 빈 자리 확인 → 없으면 스테이션에 다시 내려놓고 빈 자리 생길 때까지 대기.

### 6.2 출고 Trigger

**※ 출고 Trigger**

되담기 완료 후, 이동 로봇이 완료된 적층 Tray Unit과 빈 공정 Tray Unit을 통합 Slot 빈 자리로 이동하고, 물류 AMMR이 적층 Tray Unit은 다음 공정으로, 빈 공정 Tray Unit은 회수 자리인 세척·블라스팅 WIP으로 이동시킨다. 빈 공정 Tray Unit은 그 자리에서 물류 담당자가 회수한다.

**※ CNC WIP 통합 Slot은 되담기 완료 Unit 외에도 바로 옮기지 못하는 Unit의 임시 보관 위치로 사용된다.**

## 7. 물류 AMMR 운영 정책

이 챕터는 물류 AMMR의 외부 보고 상태값과 운영 정책을 정의한다.

### 7.1 AMMR 상태값

이 절은 AMMR이 외부 보고하는 운영 상태값(AMMR HW 상태·Slot 상태·위치·BMS)과 그 판정에 쓰이는 Manipulator Vision Sensor 감지를 정의한다. AMMR은 Core 연결 상태 알림에서 연결을 인지하거나 Core가 일괄 보고 재전송을 요청하면 초기 연결 시와 같은 일괄 보고를 재발행한다.

**※ AMMR HW 상태**

AMMR HW는 초기 연결 시 1회 일괄 보고하고, 이후 상태 전이 시점마다 Event로 보고한다. 단 Job 종료로 생기는 전이는 Job 수행 결과 보고가 함께 담는다. Job 수행 중에는 수행 중인 Job 동작을, Job이 없을 때는 운영 상태를 보고한다.

- **Move**: Move 수행 중
- **Pickup**: Pickup 수행 중
- **Dropoff**: Dropoff 수행 중
- **Charge**: Charge 수행 중 (충전 스테이션 이동·도킹)
- **대기**: 대기 중
- **충전 중**: 충전 스테이션 도킹 후 충전 중
- **저전력**: HW 자체 임계 통과 보고. Battery가 저전력 임계치(태블릿 설정값·초기값 20%) 이하로 진입한 시점. 이 상태 중 진행 중 단위 Job 종료 후 AMMR HW가 자율적으로 충전 스테이션으로 이동·도킹한다. 도킹 시점에 '충전 중'으로 전이하며, 대기 임계치(태블릿 설정값·초기값 80%) 완충 시점에 '대기'로 전이.
- **자체 충전**: Job 대기 한도(태블릿 설정값·초기값 10초)를 넘도록 새 지시가 없어 AMMR HW가 자율적으로 충전 스테이션으로 이동·도킹하는 상태. Battery 잔량과 무관하게 진입하며, 도킹 시점에 '충전 중'으로 전이하고 대기 임계치 완충 시점에 '대기'로 전이.
- **장애**: 고장 또는 수리 중. Core Dashboard 경고 표시

Move·Pickup·Dropoff·Charge·대기는 AMMR의 현재 동작을 그대로 싣는다. Core 지시 Job으로 수행하든 담당자의 티칭·테스트 조작으로 수행하든 같은 값을 보고한다.

AMMR HW가 위 9종으로 포괄되지 않는 새로운 물리 상태를 가지면, AMMR은 Core 측에 알리고 Core가 상태값 정의 확장 여부를 정한다.

**※ Slot 상태**

AMMR은 초기 연결 시 6 Slot 일괄 보고하고, 이후 사람 개입 등 외부 원인으로 상태 전이 시점에 해당 Slot 1개 보고한다. 단 Pickup·Dropoff로 생기는 상태 변화는 Job 수행 결과 보고가 함께 담는다. Slot 상태는 AMMR이 판정한다.

| 항목            | 출처      | 설명           |
|-----------------|-----------|----------------|
| Slot 상태 (6개) | AMMR 판정 | 각 Slot의 상태 |

**※ 위치**

AMMR HW는 위치 정보를 스트리밍으로 보고한다 (태블릿 설정값·초기값 1초). 단 Job 종료 시점의 위치는 Job 수행 결과 보고가 함께 담는다.

| 항목      | 출처         | 설명                                                       |
|-----------|--------------|------------------------------------------------------------|
| 현재 지점 | AMMR HW 보고 | AMMR 맵의 현재 Node ID · Node 사이를 지나는 동안은 값 없음 |
| (x, y, a) | AMMR HW 보고 | 현재 위치 좌표 + 방향각 (연속값)                           |

**※ BMS**

BMS는 다음 정보를 스트리밍으로 보고한다 (태블릿 설정값·초기값 10초).

| 항목          | 출처     | 설명                                   |
|---------------|----------|----------------------------------------|
| AMMR ID       | BMS 보고 | 이 BMS가 부착된 AMMR의 식별값          |
| Battery ID    | BMS 보고 | Battery 팩의 식별값                    |
| Battery       | BMS 보고 | 현재 충전 상태 (%, 연속값)             |
| 전류          | BMS 보고 | 현재 전류 (연속값)                     |
| 온도          | BMS 보고 | 현재 온도 (연속값)                     |
| 전압          | BMS 보고 | 현재 전압 (연속값)                     |
| BMU 오류 여부 | BMS 보고 | Battery Management Unit 오류 발생 여부 |

**※ Manipulator Vision Sensor**

AMMR HW에 부착된 Manipulator Vision Sensor는 AMMR 자체 Slot의 Unit 존재 감지 및 Vision 기반 충돌 감지를 수행한다. QR 인식 기능은 없으므로 Unit 식별값 갱신에는 별도 QR Scan이 필요하다. 두 감지 결과는 각각 Slot 상태 판정과 Job 수행 결과 보고에 실려 전달되며, 별도 보고 항목을 두지 않는다.

| **항목**            | **출처**                  | **설명**                                               |
|---------------------|---------------------------|--------------------------------------------------------|
| Slot Unit 존재 감지 | Manipulator Vision Sensor | 6 Slot 각각의 Unit 존재 여부 (Slot Sensor와 이중 감지) |
| Vision 충돌 감지    | Manipulator Vision Sensor | AMMR 작업 수행 중 Vision 기반 충돌 감지 시 보고        |

**※ 주기 일괄 보고**

AMMR은 위 운영 상태값 전체(AMMR HW 상태·6 Slot 상태·위치·BMS)에 더해 6 Slot 각각의 적재 정보(태블릿이 보관한 Slot별 Unit 식별값)를 주기적으로 일괄 자동 보고한다. 6 Slot 상태는 AMMR이 판정한 값이고, Slot별 Unit 식별값은 태블릿이 보관한 값(시스템 명령 선탑재값·시스템 회신값·담당자 입력값)으로 추정 등급이다. Core 지시 없이 일어난 외부 원인 전이에서는 그 Slot의 Core 배정 정보가 무효가 된다. 점유가 끊겼으면 태블릿은 보관 식별값을 비우고 그 Slot을 비어 있음으로 보고하며, 점유가 되살아났는데 식별되지 않으면 사용 보류로 보고한다. 발행 주기는 태블릿 설정값으로 담당자가 변경하며(초기값 60초), Core의 일괄 보고 재전송 요청·담당자 수동 발행과 별개로, Core 연결이 유효한 동안 발행된다. 단 Core 연결을 인지해 일괄 보고를 재발행하면 그 시점부터 주기를 다시 잰다.

### 7.2 AMMR 태블릿 설정값

AMMR 운영에 필요한 다음 설정값은 AMMR 태블릿에서 담당자가 변경하며, AMMR 내부에 저장되어 재시작 후에도 유지된다. 이 설정값은 Core 측에 별도 저장되지 않는다.

**※ 설정 항목**

| 항목                     | 초기값 | 비고                                                                            |
|--------------------------|--------|---------------------------------------------------------------------------------|
| 시스템 Host IP           | -      | AMMR이 Core MQTT Broker에 접속할 IP 주소                                        |
| 시스템 포트              | -      | Core MQTT Broker 접속 포트                                                      |
| MQTT 접속 ID             | -      | Core MQTT Broker 접속 자격증명                                                  |
| MQTT 접속 비밀번호       | -      | Core MQTT Broker 접속 자격증명                                                  |
| 일괄 보고 주기           | 60초   | AMMR이 운영 상태값 전체를 주기 자동 일괄 보고하는 간격                          |
| 위치 보고 주기           | 1초    | AMMR이 위치 정보를 스트리밍 보고하는 간격                                       |
| BMS 보고 주기            | 10초   | BMS가 정보를 스트리밍 보고하는 간격                                             |

| 충전 스테이션 번호       | -      | AMMR이 충전 시 이동할 스테이션 번호 (자율 충전·자체 충전·Core Charge 지시 공통) |
| Battery 대기 임계치      | 80%    | '충전 중' → '대기' 전이 판단 기준값                                             |
| Battery 저전력 임계치    | 20%    | '저전력' 진입 판단 기준값                                                       |
| Job 대기 한도            | 10초   | 새 Job 지시 없이 대기가 이어질 때 충전 스테이션으로 자율 복귀하는 기준값        |
| Move 수행 한도           | 5분    | Move Job 동작을 마쳐야 하는 한도                                                |
| Pickup·Dropoff 수행 한도 | 5분    | Pickup·Dropoff Job 동작을 마쳐야 하는 한도                                      |
| 설비 Interlock 대기 한도 | 3분    | 설비 Interlock 신호 확보를 기다리는 한도                                        |

**※ 설정값 변경 제약**

위 설정 항목은 모두 Core 연결이 끊긴 상태에서만 변경 가능하다.

### 7.3 AMMR Job 배정 정책

**※ Pickup 우선순위**

Core는 Pickup 대상 Unit이 여럿인 경우 우선순위가 높은 Unit부터 배정한다. 물류 AMMR은 배정받은 Job을 수행할 뿐 우선순위를 판단하지 않는다.

**※ 신규 Job 배정 조건**

AMMR HW 상태가 '저전력'·'자체 충전' 또는 '충전 중'인 동안 Core는 신규 Job 배정을 차단한다. 단, '충전 중'에 한해 Core가 필요하다고 판단하면(대표 사례 = 충전으로 Battery 충분히 회복) 충전 완료를 기다리지 않고 이 AMMR에 신규 Job을 배정하거나 적재 중 Unit의 진행 Job을 이어간다. 이 지시를 받으면 AMMR은 충전을 중단하고 충전 스테이션에서 이탈한 뒤 Job을 수행한다. '저전력' 중에는 이 예외가 없으며, 이 상태에서 지시가 수신되면 AMMR은 수신 확인 보고는 보내되 수행 없이 저전력 사유로 실패를 회신한다.

### 7.4 AMMR Job 지시 수신 확인 정책

Core는 Job 지시 후 AMMR이 보고하는 Job 지시 수신 확인 보고를 수신한다. 이 보고는 AMMR HW가 Job 지시를 수신한 직후 송신된다.

**※ 수신 확인 보고 시한**

AMMR은 Job 지시를 받으면 정해진 시한 안에 수신 확인을 보고해야 한다. 시한 값은 운영 결과와 AMMR 통신 지연 특성에 따라 조정한다.

**※ 계약에 어긋난 지시 수신 시 처리**

지시에 필요한 값이 빠졌거나 그 AMMR의 것이 아닌 위치를 가리키는 등 계약에 어긋난 지시가 수신되면, AMMR은 수신 확인 보고는 보내되 수행 없이 지시 결손 사유로 실패를 회신한다. 같은 지시가 자동으로 다시 오지는 않으며, 이 사유는 Core Dashboard 경고로 표시해 운영자가 인지한다.

### 7.5 AMMR Job 수행 전 Slot 상태 확인 원칙

물류 AMMR의 Pickup·Dropoff 동작 직전에 대상 Slot의 상태를 재확인한다. 정합성 이상 감지 시 해당 Slot 정합성 이상 처리 + 보안 Log + Core Dashboard 경고가 발생한다.

**※ 재확인이 필요한 이유**

사람이 현장에서 Slot의 Unit을 임의로 이동·교체·회수할 수 있다. 점유가 끊기는 개입은 클라이언트가 Slot 상태 전이로 즉시 보고해 그 Slot이 비고, 걸려 있던 배정과 진행 중 작업이 무효가 된다. 다시 점유됐는데 식별되지 않으면 그 시점에 사용 보류로 넘어간다. 점유가 끊기지 않는 맞바꿈은 Sensor에 전이가 남지 않아 감지되지 않으며, 다음 공정 입고 QR 인식 시점에 드러난다. 이때 그 Slot을 사용 보류로 둘지 실물 QR 값 기준으로 계속 진행할지는 시스템 설정값으로 정하며, 어느 쪽이든 보안 Log 기록과 Core Dashboard 경고는 남는다. AMMR Job 직전 재확인은 이렇게 반영된 Slot 상태를 동작 직전에 다시 확인하는 장치다.

**※ 정합성 회복 절차**

Slot 정합성 이상은 원인이 저절로 사라지지 않으므로 담당자가 정합성 회복 조치(권위 데이터 갱신)를 수행해야 하며, 그 조치로 정합성이 회복되면 별도 사용자 명령 없이 자동 해제된다. 식별값이 어긋나 생긴 이상은 그 Slot의 실물을 보는 단말에서 받는다. WIP 프로그램은 WIP Dashboard, AMMR은 태블릿 적재 정보 일괄 재로드, CNC 작업대는 작업 실적 화면이다. Unit이 갈 수 없는 공정으로 들어와 생긴 사용 보류는 식별값을 고쳐도 풀리지 않는다. 담당자가 작업 실적 화면에서 빠진 공정의 종료를 기록하거나 잘못 남긴 기록을 취소해 순서가 맞아떨어지면 풀리며, 그 Unit을 가져가 Slot이 비어도 풀린다. 이 조치는 보안 Log 기록 대상이다.

**※ AMMR Slot 적재 정보 일괄 재로드**

AMMR 자체 Slot의 정합성 회복은 적재 정보 일괄 재로드로 수행한다. 주기 일괄 보고가 6 Slot의 상태와 Slot별 Unit 식별값을 상시 올리므로, 재로드는 담당자가 태블릿에서 Slot별 Tray ID를 고쳐 입력한 뒤 이 일괄 보고를 즉시 한 번 수동 발행하는 것이다. 고친 값은 재연결 시점의 일괄 보고에 실려 수동 발행 없이도 자동 전달되며, 재로드는 이를 즉시 보내는 동작이다. Core는 보고된 Slot 상태·Unit 식별값을 확정 배정과 대조해, 어긋난 Slot이 있으면 6 Slot 전체를 확정 Unit 정보·Job 배정으로 정정 응답하며, 정합이 회복된 Slot은 이상이 자동 해제된다. 재로드는 전부 일치해도 응답이 오며, 담당자는 이 응답 도착으로 성공을 판정한다. 수동 발행 뒤 3초 안에 응답이 없으면 실패로 안내되고 담당자가 다시 시도한다. 주로 통신 단절 중 사람이 AMMR Slot의 Unit을 임의로 다룬 뒤 재연결 시점에 상태를 다시 맞추는 데 쓴다. 이 조치는 보안 Log 기록 대상이다.

### 7.6 AMMR 적재 Unit 추정값 정책

AMMR이 현재 싣고 있는 Unit 목록은 추정값이며, Pickup 동작 시 출발 Slot의 QR Scan 정보를 기반으로 추정된다. Dropoff 시점에 도착 Slot의 QR Scan 정보로 보정되며, 보정이 없으면 후속 QR Scan 시점까지 추정 등급이 유지된다. 이 추정 식별값은 주기 일괄 보고에 실려 상시 보고된다.

**※ 추정값 오보정 시나리오**

| 시나리오       | 발생 원인                                  | 처리 |
|----------------|--------------------------------------------|---|
| 적재 Unit 교체 | 사람이 AMMR 위의 Unit을 다른 Unit으로 바꿈 | 점유가 끊기면 Slot 상태 전이 보고로 배정 무효 후 새 점유가 식별되지 않아 사용 보류 · 끊기지 않으면 다음 공정 입고 QR 인식 시점에 드러남 + Core Dashboard 경고 + 보안 Log 기록 |
| 적재 Unit 소실 | 사람이 AMMR 위의 Unit을 가져감             | 점유가 끊기므로 Slot 상태 전이 보고로 비어 있음이 올라와 배정 무효 → 보안 Log + Core Dashboard 경고 |

**※ 추정값도 재판단 및 우선순위 계산에 활용된다. 추정값은 다음 QR Scan 시점에 실제값으로 보정되므로 시스템 정합성은 유지된다.**

### 7.7 AMMR 장애 대응 정책

이 절의 '장애'는 AMMR HW 상태 '장애' 또는 AMMR HW 단절로 운영 불가 묶음을 가리킨다.

**※ AMMR 장애 상황별 처리**

| 상황      | 처리                                                                |
|-----------|---------------------------------------------------------------------|
| 장애 발생 | Core Dashboard 경고 / 해당 AMMR 운영 불가 표시                      |
| Unit 처리 | 사람이 직접 꺼내서 다음 or 이전 공정에 배치 → QR Scan으로 위치 기록 |
| 1대 운영  | 처리 속도 저하 주의 표시                                            |
| 0대 운영  | Core Dashboard 전체 정지 경고 / 사람이 수동 대응                    |

**※ 장애 중 지시 수신 시 처리**

'장애' 상태에서 지시가 수신되면 AMMR은 수신 확인 보고는 보내되 수행 없이 장애 사유로 실패를 회신한다. 장애 진입 시점에 수행 대기 중이던 지시도 같은 방식으로 실패를 회신하고 폐기한다. 장애 복구 후에도 이 지시들을 소급 수행하지 않으며, 필요한 작업은 Core가 새로 지시한다.

**※ Job 수행 한도 초과**

AMMR은 Move·Pickup·Dropoff 각각에 수행 한도를 두고, 한도 안에 동작을 마치지 못하면 수행을 중단하고 한도 초과 사유로 실패를 회신한다. 한도는 태블릿 설정값이며 초기값은 Move 5분, Pickup·Dropoff 5분이다. Core는 그 AMMR의 위치·적재 정보를 비우고 6 Slot을 사용 보류로 둔다. 담당자가 현장을 확인한 뒤 적재 정보를 다시 올려 사용 보류를 푼다. 담당자 티칭·테스트 조작으로 수행한 동작에도 같은 한도가 걸린다. 이때는 회신할 Job이 없어 AMMR이 수행만 중단하고 Core에 알리지 않는다.

**※ AMMR Slot 정합성 이상이 발생한 경우 해당 Slot을 제외한 나머지 Slot으로는 정상 운영을 계속한다.**

**※ 통신 단절 시 자동 재연결 한도**

AMMR은 Broker 연결이 끊기면 1초 간격으로 재연결을 시도하고, 재연결 한도(태블릿 설정값·초기값 5분)가 지나도록 회복되지 않으면 자동 시도를 멈춘다. 이후 연결은 담당자가 태블릿에서 직접 실행한다.

**※ 담당자에 의한 명시적 연결 해제·재연결**

담당자가 AMMR 태블릿에서 시스템 연결을 명시적으로 해제·재연결하는 동작을 AMMR이 지원한다. 이 동작에 의한 단절·재연결은 통상 단절·재연결 흐름과 동일하게 처리된다.

담당자가 티칭·테스트 조작으로 AMMR을 직접 움직일 때는 시스템 연결을 해제한 상태에서 수행한다. 연결이 유효한 동안에는 Core가 그 AMMR을 배정 대상으로 두므로 조작 중에 Job이 지시될 수 있다.

### 7.8 AMMR 설비 측 실패 처리

물류 AMMR이 Pickup·Dropoff를 수행할 때 설비 쪽 접점에서 막혀 동작하지 못하는 경우가 있다. 위치 기준 Marker를 읽지 못해 위치를 맞추지 못한 경우와, CNC WIP의 설비 Interlock 신호를 확보하지 못한 경우다. 설비 Interlock 신호는 대기 한도(태블릿 설정값·초기값 3분) 안에 확보하지 못하면 확보 실패로 판정한다. 두 경우 모두 AMMR은 수행을 중단하고 설비 측 사유로 실패를 회신한다.

이 보고만으로는 AMMR 쪽 문제인지 설비 쪽 문제인지 가릴 수 없다. 따라서 Core는 해당 Job을 실패로 닫고, 그 AMMR의 위치·적재 정보를 비우고 6 Slot을 사용 보류로 둔다. 같은 지시를 자동으로 다시 내지 않는다. 담당자가 현장을 확인한 뒤 적재 정보를 다시 올려 사용 보류를 푼다. 사유는 Core Dashboard 경고로 표시해 운영자가 인지한다.

## 8. 외부 시스템 통신

이 챕터는 Core가 연동하는 외부 시스템·물류 AMMR·Core Dashboard와의 통신을 정의한다. 각 외부 시스템별로 통신 방식, 데이터 종류, 동기화 정책, 오류 처리 원칙을 다룬다.

**※ 외부 시스템 통신 개요**

| **외부 시스템**        | **통신 방향**                     | **프로토콜**       |
|------------------------|-----------------------------------|--------------------|
| GM                     | Core → GM (폴링)                  | REST API           |
| SM                     | Core → SM (폴링)                  | REST API           |
| 일반 공정 WIP 프로그램 | WIP 프로그램 → Core (Event)       | REST API           |
| CNC WIP 프로그램       | WIP 프로그램 → Core (Event)       | REST API           |
| 물류 AMMR              | AMMR ↔ Core (스트리밍·Event·명령) | MQTT               |
| Core Dashboard         | Core ↔ Core Dashboard (Push·명령) | SignalR + REST API |
| 독립 프로그램          | 독립 프로그램 → Core (REST 호출)  | REST API           |

Core의 외부 시스템 통신은 크게 세 가지 패턴으로 나뉜다. GM/SM은 Core가 직접 폴링하여 데이터를 가져오는 구조이고, WIP 프로그램·물류 AMMR·독립 프로그램은 외부 측이 Event·스트리밍 발생 시 Core에 전달하는 구조이며, Core Dashboard는 Core가 운영 상태를 Push로 전달하고 사용자 명령은 Core Dashboard가 REST API로 송신하는 양방향 구조이다.

이 챕터의 WIP 프로그램들과 물류 AMMR은 모두 HW 제어를 직접 담당하는 외부 구성요소이며, Core는 통신만 담당한다. 외부 구성요소의 내부 구현(Sensor 폴링 주기, 제어 로직, 물리적 수행 세부 등)은 Core 설계 범위 밖이다.

### 8.1 GM 시스템 통신

GM은 Core 외부에 존재하는 시스템으로, 생산관리시스템 역할을 한다. Core는 GM에서 작업 진행에 필요한 정보를 가져와야 한다.

**※ 외부 측 통신 제약**

GM은 REST API만 제공하며 Push를 지원하지 않는다.

**※ Core가 수신하는 데이터**

| **항목**  | **용도**                                        |
|-----------|-------------------------------------------------|
| 제품 정보 | Unit 구성 (수량·완료목표일·제품 속성 포함)      |
| Recipe    | Unit의 공정 흐름 정의 (공정 순서·공정별 가공처) |

**※ GM 제품 목록**

GM이 Core에 보내는 목록에 있으면 그 제품은 진행 대상이고, GM에서 삭제되면 목록에서 사라진다. 목록에 넣고 빼는 권위는 GM 측에 있으며, 사람이 GM 측에서 완료 처리하거나 투입코드를 삭제하면 목록에서 빠진다.

투입코드는 GM 전체에서 유일한 값이며, Core는 이를 제품 진행 단위로 추적한다. 한 번 빠진 제품이 다시 목록에 돌아오는 경우는 발생하지 않는 것을 전제로 한다. 다시 진행해야 하면 GM 측에서 신규 제품으로 재등록한다.

**※ 데이터 동기화 정책**

**※ 확정 시점은 QR 발행(=Unit 구성) 시점이다. 확정 전의 GM 데이터 변경은 자유롭게 반영한다. 한 투입코드에서 Unit이 하나라도 발행되면 그 투입코드는 발행 시점 값으로 굳으며, 이후 Core가 계속 보는 것은 완료목표일과 목록 존재 여부뿐이다. 굳은 뒤에도 남은 입고분의 Unit 발행은 그 값을 기준으로 이어간다.**

| **데이터 항목**                   | **확정 후** | **GM 측 변경 시 영향**                 |
|-----------------------------------|-------------|----------------------------------------|
| 제품 속성 (모델·버전·부품명·용도) | 변경 무시   | 발행 시점 값으로 이어서 진행           |
| 수량 (GM 원본 투입 수량)          | 변경 무시   | 이미 발행된 Unit 수는 변경되지 않음    |
| 완료목표일                        | 변경 반영   | 변경된 완료목표일로 우선순위 다시 계산 |
| Recipe                            | 변경 무시   | 발행 시점 Recipe로 끝까지 진행         |
| 목록 존재 여부                    | 계속 확인   | 목록에서 빠지면 목록 이탈로 처리       |

확정 후 제품 속성이나 Recipe를 바꿔야 하는 상황이면 담당자가 그 제품의 Unit을 먼저 회수한 뒤 GM에서 변경한다. 회수 없이 GM 값만 바꾸면 이미 발행된 Unit은 바뀐 정보를 따르지 않는다.

GM 목록에는 완료목표일이 지난 오더도 진행 상태로 남아 있을 수 있다.


### 8.2 SM 시스템 통신

SM은 Core 외부에 존재하는 시스템으로, 장비/CNC 작업대 모니터링 시스템 역할을 한다.

**※ 외부 측 통신 제약**

SM은 REST API만 제공한다.

**※ Core가 수신하는 데이터**

| **항목**                     | **용도** |
|------------------------------|---|
| 공정-CNC 작업대 Mapping 정보 | 어느 CNC 작업대가 어느 제품의 CNC 몇 공정을 담당하는지 식별. 제품은 모델과 버전 두 값으로 온다 |
| CNC 작업대 Slot Sensor 신호  | CNC 작업대 Slot Sensor On/Off 값. 입고·출고 시점 판단 + CNC 작업대 점유 상태 판정 |
| 장비 상태                    | CNC 작업대의 장비 상태 — 대기·작업 중·예열·통신 끊김 |

Slot Sensor 신호와 Mapping 정보는 조합되어야 의미가 있다. Sensor 신호만으로는 어느 공정인지 알 수 없고, Mapping 정보만으로는 현재 상태를 알 수 없다. 장비 상태는 이와 별개로 CNC 작업대 자체의 상태를 나타낸다.

### 8.3 일반 공정 WIP 프로그램 통신

일반 공정 WIP 프로그램은 일반 공정 WIP의 HW 장비 및 QR 인식 수단과 Core를 잇는 외부 프로그램이며, WIP Dashboard를 갖는다(화면 구성은 WIP 측 자율). 담당자는 이 UI로 Slot별 Tray QR을 입력하고, WIP 프로그램은 자기 Slot Sensor와 보유 Unit 정보로 Slot 상태와 입고/출고를 자체 판정해 Core에 보고한다. Core는 그 Unit에 대한 정보를 응답 API로 되돌려 준다.

**※ 외부 측 통신 제약**

REST API만 제공. WIP 프로그램이 Core를 호출하는 방향이다. 호출 시점은 (a) Event 발생 시 (b) HealthCheck 주기(예: 10초). HealthCheck 주기는 외부 측 보장 값으로 Core가 판단의 전제로 활용한다.

WIP 프로그램은 주기적으로(예: 60초) 전체 Slot의 상태와 Slot별 Unit 식별값을 동반 전송한다. Core는 확정 배정과 대조해 어긋난 Slot을 정정 응답한다. 또한 다음 두 경우의 부활 시점 첫 호출에도 같은 전체 상태를 동반한다 — (가) WIP 프로그램 자기 측 단절 인지 후 복귀, (나) Core 측 무응답 지속 후 응답 재개.

**※ Core가 수신하는 Event**

| **Event**      | **내용** |
|----------------|---|
| Slot 상태 판정 | WIP 프로그램이 판정한 Slot 상태 변화 |
| 입고/출고 판정 | QR Scan으로 확정된 Unit 식별 정보 + Slot 위치 + WIP 프로그램이 판정한 입고/출고 구분값 |

**※ Core가 송신하는 데이터** (Core → WIP 프로그램)

| **항목**                                     | **Trigger** |
|----------------------------------------------|---|
| Unit 정보 (식별값·Recipe를 포함한 제품 정보) | WIP 프로그램 보고(Slot 상태·입출고 판정) 수신 시. WIP Dashboard 표시·PLC 운영에 사용. |
| 사용 가능 여부 판정                          | 입고 보고 수신 시. 그 Unit을 이 설비의 공정에서 쓸 수 있는지에 대한 Core 판정. |
| Slot 사용 보류 판정                          | WIP 프로그램 보고 수신 시. Core 판정으로 그 Slot을 쓸 수 없게 된 사실과 그 사유. WIP Dashboard에 표시한다. |
| Slot 복귀 판정                               | 이송이 출발 Slot으로 되돌아온 경우. 그 Slot의 Unit 식별값과 되돌린 사유. WIP 프로그램은 이 값으로 자기 상태를 되돌리고 WIP Dashboard에 사유를 표시한다. |

### 8.4 CNC WIP 프로그램 통신

CNC WIP 프로그램은 일반 공정 WIP 프로그램의 역할에 더해, 되담기 작업 완료 정보를 Core에 전달하는 역할을 담당한다. 일반 공정 WIP과 같이 WIP Dashboard를 가지며(화면 구성은 WIP 측 자율), Slot Sensor·보유 Unit·Pair 판단으로 Slot 상태를 자체 판정한다. Pair가 갖춰지지 않아 대기 중인 Slot은 Pair 대기로 보고한다.

**※ 외부 측 통신 제약**

REST API만 제공. CNC WIP 프로그램이 Core를 호출하는 방향이다. 호출 시점은 (a) Event 발생 시 (b) HealthCheck 주기(예: 10초). HealthCheck 주기는 외부 측 보장 값으로 Core가 판단의 전제로 활용한다.

CNC WIP 프로그램은 주기적으로(예: 60초) 전체 Slot의 상태와 Slot별 Unit 식별값을 동반 전송한다. Core는 확정 배정과 대조해 어긋난 Slot을 정정 응답한다. 또한 다음 두 경우의 부활 시점 첫 호출에도 같은 전체 상태를 동반한다 — (가) CNC WIP 프로그램 자기 측 단절 인지 후 복귀, (나) Core 측 무응답 지속 후 응답 재개.

**※ Core가 수신하는 Event**

| **Event**      | **내용** | **비고**                  |
|----------------|---|---------------------------|
| Slot 상태 판정 | WIP 프로그램이 판정한 Slot 상태 변화 (Pair 대기 포함) | 일반 공정 WIP + Pair 대기 |
| 입고/출고 판정 | QR Scan으로 확정된 Unit 식별 정보 + Slot 위치 + WIP 프로그램이 판정한 입고/출고 구분값 | 일반 공정 WIP과 동일      |
| 되담기 완료    | Tray ID + 되담기 완료 여부 + 적층 구성 리스트(어느 적층 Tray에 어떤 제품을 담았는지) + 빈 공정 Tray Unit 식별값 리스트 | CNC WIP 고유              |

**※ Core가 송신하는 데이터** (Core → CNC WIP 프로그램)

| **항목**                                     | **Trigger** |
|----------------------------------------------|---|
| Unit 정보 (식별값·Recipe를 포함한 제품 정보) | WIP 프로그램 보고 수신 시. WIP Dashboard 표시·자체 Pair 판단에 사용. |
| 사용 가능 여부 판정                          | 입고 보고 수신 시. 그 Unit을 이 설비의 공정에서 쓸 수 있는지에 대한 Core 판정. |
| Slot 사용 보류 판정                          | WIP 프로그램 보고 수신 시. Core 판정으로 그 Slot을 쓸 수 없게 된 사실과 그 사유. WIP Dashboard에 표시한다. |
| Slot 복귀 판정                               | 이송이 출발 Slot으로 되돌아온 경우. 그 Slot의 Unit 식별값과 되돌린 사유. WIP 프로그램은 이 값으로 자기 상태를 되돌리고 WIP Dashboard에 사유를 표시한다. |

### 8.5 물류 AMMR 통신

물류 AMMR은 Core 외부에 존재하는 자율주행 로봇으로, Unit의 외부 이동을 담당한다. 현재 2대 운영.

**※ 외부 측 통신 제약**

AMMR HW와 Core는 MQTT 프로토콜로 통신한다. AMMR HW 단절은 MQTT Last Will로 Core가 인지한다. 단, 짧은 통신 순단이 유예 시간(10초) 내 재연결로 복구되면 AMMR HW 단절로 처리하지 않으며, 유예 시간을 초과한 단절만 AMMR HW 단절로 처리한다. 이 유예 시간은 Core가 정하는 값이며, AMMR이 임의로 바꾸지 않는다. 현장 사정으로 값을 바꿔야 하면 Core 측에 알린다. Core 단절도 같은 방식으로 Core 연결 상태 끊김 통지를 받아 AMMR이 인지한다(위 순단 유예는 AMMR HW 단절 판정에 대한 서술이다).

**※ Core가 수신하는 데이터** (AMMR → Core)

AMMR이 보고하는 운영 상태값(HW 상태·위치·BMS·Slot 상태)과 6 Slot 각각의 적재 정보(Slot별 Unit 식별값), Job 지시 수신 확인 보고(Job 지시 직후), Job 종료 시점의 Job 수행 결과 보고(Move·Pickup·Dropoff·Charge)를 수신한다. AMMR은 설정값 조회 요청을 받으면 태블릿에 설정된 현재 운영값을 보고한다.

**※ Core가 송신하는 데이터** (Core → AMMR)

| 항목 | Trigger                                                              |
|---|----------------------------------------------------------------------|
| Job 지시 (Move·Pickup·Dropoff·Charge · 각 Job 지시는 고유 식별값을 갖는다) | Job 결정 시점                                                        |
| 일괄 보고·재로드에 대한 정합 정정 응답 (확정 배정과 어긋날 때 6 Slot 전체의 확정 Unit 정보·Job 배정) | 일괄 보고·재로드 수신 시 (재로드는 항상·그 밖은 확정 배정 불일치 시) |
| Core 연결 상태 알림 (전체 AMMR 대상 — 연결·끊김 두 값. AMMR은 연결을 인지하면 운영 상태값 일괄 보고를 다시 발행하고 위치·BMS 스트리밍을 재개하며, 끊김을 인지하면 태블릿에 시스템 연결 끊김을 표시하고 두 스트리밍과 주기 일괄 보고를 멈춘다) | Core 연결 상태 변화 시점                                             |
| 운영 상태값 일괄 보고 재전송 요청 | Core가 특정 AMMR 상태를 즉시 재수신해야 할 때                        |
| 태블릿 설정값 조회 요청 (설정값의 단일 소스는 태블릿이며 Core는 보유하지 않는다) | Core가 현장 설정값을 확인해야 할 때                                  |

AMMR에 Mount된 태블릿은 Job 지시에 선탑재된 Unit·위치 정보와 자기 Slot 상태 판정으로 적재 상태·배정 상태·상단 정보 영역 화면을 자체 구성하며, 정합이 어긋나면 Core 정정 응답으로 보정한다. 상단 정보 영역은 태블릿이 아는 값(HW 상태·최근 명령·명령 Slot 등)으로 구성한다. 태블릿은 AMMR과 함께 Core와 MQTT로 통신하는 단말이며, 별도 통신 채널을 사용하지 않는다.

**※ AMMR HW 자율 동작 영역**

도킹·충전·이탈 등 물리적 수행 세부와 자체 임계에 따른 충전 중단 결정은 AMMR HW가 자체 처리한다. Core는 Job 수행 결과 보고만 수신한다. 자율 주행(위치 측위·경로 결정·물리적 이동 수행 세부)도 AMMR HW 영역이다. AMMR HW 정지·리셋·재시작 등 HW 생명주기 제어도 AMMR 업체 영역이며, Core는 물류 Job(Move·Pickup·Dropoff·Charge)만 지시한다.

### 8.6 Core Dashboard 통신

Core Dashboard는 Core 외부에 존재하는 클라이언트 애플리케이션으로, 운영자가 시스템 상태 조회·수동 명령을 수행하는 단말기 역할을 한다.

**※ 외부 측 통신 제약**

Core Dashboard는 두 채널을 사용한다 — Core가 운영 상태를 SignalR로 실시간 Push하고, Core Dashboard가 사용자 명령을 REST API로 송신한다.

**※ Core가 송신하는 데이터** (Core → Core Dashboard, SignalR Push)

| 항목                                                                            | Trigger           |
|---------------------------------------------------------------------------------|-------------------|
| 운영 상태 변화 (Slot 상태·Unit 식별값·AMMR 상태·Job 진행 등)                    | 상태 변화 발생 시 |
| 경고 (병목·장애·사용 보류 등, 병목과 운영 가능 AMMR 수는 주의·경고 단계별 구분) | 경고 발생·해제 시 |

**※ Core Dashboard가 송신하는 데이터** (Core Dashboard → Core, REST API)

| 항목                                             | 용도                     |
|--------------------------------------------------|--------------------------|
| 사용자 명령 (시스템 설정·계정·접근 제어 관리 등) | 사용자 명령 처리 Trigger |

### 8.7 독립 프로그램 통신

독립 프로그램(QR 발행·Unit 관리·작업 실적)은 Core 외부에 존재하는 클라이언트 애플리케이션으로, 사용자가 Unit 발행·외주 관리·Unit 구성 조회·편집·작업 실적 입력을 수행하는 단말기 역할을 한다. 작업 실적은 사람이 수동 입력하는 것 외에 CNC 공정 AMMR이 자율 보고로 올리기도 한다.

**※ 외부 측 통신 제약**

독립 프로그램은 사용자 명령·조회와 외부 측 자율 보고를 REST API로 Core에 호출한다. Core가 먼저 상태를 밀어 주는 채널은 없다.

**※ 독립 프로그램이 송신하는 데이터** (독립 프로그램 → Core, REST API)

| 항목 | 용도                                             |
|---|--------------------------------------------------|
| 사용자 명령 (Unit 구성 확정·적층 Tray 입고 등록·외주 배차 확정·복귀 등록·Unit 구성 편집·작업 실적 수동 입력·수동 되담기 완료 등록·공정 기록 취소·Unit 식별값 수동 입력 등) | 사용자 명령 처리 Trigger                         |
| 공정 작업 시작·종료 보고 (CNC 공정 AMMR 또는 사람 QR Scan) | 작업 시각 기록 (외부 측 자율 보고·없으면 미기록) |

## 10. Recipe 및 공정 조회

이 챕터는 Unit에 부속된 Recipe의 소유·조회 정책을 정의한다.

### 10.1 Recipe 소유·조회

Recipe는 GM이 소유하며, 투입 단위로 Unit에 부속되어 전달된다. 같은 투입코드로 생성된 Unit들은 그 투입의 Recipe를 공유한다. Core는 Unit별로 부속된 공정 순서를 조회·추적하며, GM이 전달한 Recipe 자체는 고치지 않는다. 다만 운영 중 Recipe에 없는 경유 공정이 필요해지면 그 공정을 그 Unit의 다음 공정으로 배정한다. 임시 보관·대기로 배정된 Unit은 사유가 해소되면 원래 다음 공정으로 복귀하고, 담당자 인계를 위해 배정된 Unit은 그 자리에서 흐름이 종결된다. 자동 추적 대상이 아닌 공정은 사람이 직접 수행한 뒤 작업 실적 화면에서 종료를 기록한다. 같은 공정이 Recipe에 여러 번 있어 지금 어느 회차인지 가릴 수 없는 Unit이 설비에 들어오면 그 Slot을 사용 보류로 둔다. Unit별로 다른 공정 흐름이 필요한 경우 GM이 투입 단계에서 구분해 전달한다.

작업 실적 화면에서는 입고·작업 시작·작업 종료·출고 네 기록을 각각 취소할 수 있다. 취소 요청은 담당자가 언제든 낼 수 있고 시스템이 판정한다. 등록된 기록이 있어야 하고 입고·출고 취소는 그 Slot이 빈 뒤여야 하며, 어긋나면 무엇 때문인지 사유와 함께 실패를 돌려준다. 입고 취소는 그 공정에 들어온 사실을 되돌린다. 작업 시작 취소는 시각 기록만 지운다. 작업 종료 취소는 자동 추적 대상이 아닌 공정과 수동 되담기 완료를 등록한 공정에서 그 공정을 마치지 않은 것으로 되돌리며, 출고 취소도 같은 효과를 낸다.

**※ 조회 기능**

- Unit별 공정 조회: 현재 Unit의 공정 순서 확인

## 13. 장애 대응 및 복구 정책

이 챕터는 Core 시스템·외부 구성요소의 장애 대응과 복구 정책을 정의한다.

### 13.1 Core 다운 시 대응

이 절은 Core 다운 시 시스템·외부 구성요소의 동작과 부활 시 자연 정합 회복을 정의한다.

**※ Core 다운 시 Core Dashboard 사용자 명령 차단**

Core 다운을 Core Dashboard가 감지한 동안에는 사용자 명령 입력을 차단한다. 사용자의 명령이 실패하지 않도록 입력 자체를 막아 운영 안전을 확보한다. Core 복구 시 자동으로 정상 운영 화면으로 복귀한다.

**※ Core 다운 중 물류 AMMR 자율 동작**

Core 다운 중 진행 중이던 Job은 완료까지 수행하며, 완료 후 AMMR은 그 자리에서 대기한다. 대기가 Job 대기 한도를 넘으면 자체 충전으로 충전 스테이션에 복귀하고, 저전력에 들면 자율 충전으로 이동·충전·완충한다. 두 동작 모두 AMMR HW 자체 동작이므로 Core 다운 여부와 무관하게 자연 작동한다.

**※ Core 부활 시 자연 정합 회복**

Core 부활 시 외부 시스템·AMMR과의 통신이 자동 재연결되며, 데이터를 자동 재수신하여 자연 정합 상태로 복구된다. AMMR은 Core 연결 상태 알림에서 연결을 인지하면 운영 상태값 일괄 보고를 다시 발행하므로, AMMR 측 재연결이 없어도 재수신이 이뤄진다. 정상 경로에서는 담당자의 별도 조치가 필요 없다. 다만 태블릿에도 보관 식별값이 없는 Slot은 담당자가 태블릿에서 값을 채워 다시 보고해야 한다.
