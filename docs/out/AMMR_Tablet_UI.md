## 문서 안내

이 문서에서 시스템 측은 AMMR 외부의 운영 시스템 일체를 가리킵니다.

이 문서는 태블릿 화면을 어떻게 구성하면 좋을지 제안드리는 문서입니다. 화면 디자인·색·폰트·아이콘·배치·버튼 형태·표기 기호는 모두 업체에서 자유롭게 정해 주시면 되고, 본문에 나오는 예시와 뒤쪽 UI 모형도 참고용입니다.

다만 아래 세 묶음만은 본문에 적힌 그대로 맞춰 주시기를 부탁드립니다. 화면에 보이는 값이 시스템이 보낸 값과 어긋나면 현장에서 문제가 생겼을 때 원인을 짚기 어려워지기 때문입니다.

- **값을 가공 없이 그대로 표시**: HW 상태(`hw_state`)·최근 명령(`job_type`)·현재 Node ID(`node_id`)·좌표·방향각·출발/도착 설비 ID·Job 실패 사유 코드(`reason`)·HW 전이 사유 코드(`reason`)·재요청 거절 사유 코드(`reason`)
- **어휘와 형식**: Unit 라벨 형식(`투입코드_유닛번호`)·Log 분류 3종(`시스템 → AMMR`·`AMMR → 시스템`·`설정 변경`)·Log 화면 시간 칸 표기(메시지 timestamp 형식)
- **동작 조건**: 설정 네 영역의 [편집]/[저장] 편집 방식·설정 화면 입력 박스와 [일괄 보고 재로드] 버튼의 활성 조건·시스템 접속 영역의 연결 버튼이 연결 상태에 따라 [연결]/[해제]로 바뀌는 한 버튼이고 [편집]으로 입력이 열린 동안 비활성인 것·재로드 응답을 응답 대기 한도만큼 기다리는 것·시스템 연결 판정(MQTT 연결과 Core 연결 두 축)·시스템 연결이 끊긴 동안의 표시 방식(시스템 권위 값만 빈값·AMMR 권위 값 유지)·미점유로 판별된 Slot의 값 비움·진행 한도로 어느 한도의 남은 시간을 띄울지·수동 조작 화면의 티칭·테스트 조작 그룹이 수동 모드에서만 열리는 것·원점 복귀 두 버튼이 수동 모드이거나 장애 상태이고 로봇팔이 원점이 아닐 때만 활성화되는 것·운전 모드를 바꾸거나 태블릿을 켜면 자동은 적재 상태 화면, 수동은 수동 조작 화면으로 바뀌는 것·운전 모드를 AMMR이 보유해 재접속 후에도 유지하고 재시작하면 수동으로 시작하는 것·운전 모드 버튼이 Pickup·Dropoff를 수행하는 동안(티칭 조작 포함·도중 일시 정지·그 뒤 원점 복귀 포함) 비활성인 것·[최근 명령 재요청] 버튼이 시스템 연결 중·자동 모드·HW 상태 idle·charging·docked이고 최근 명령이 있을 때만 활성인 것과 누른 뒤의 잠금과 해제(누른 순간부터 재지시 명령이나 거절 도착 또는 대기 실패까지)·재요청 직전에 일괄 보고를 먼저 발행하고 그 응답을 받은 뒤 요청하는 것·일괄 보고 응답·수신 확인·재지시 명령을 각각 응답 대기 한도만큼 기다리는 것·Slot 상태 전이와 재요청 중 받은 다른 명령의 거부를 하단 안내 줄에 띄우지 않는 것·[작업 취소] 버튼이 자동 모드에서 이동 명령을 수행하는 동안에만 활성화되는 것·[Reset] 버튼이 항상 활성이되 장애 중에는 로봇팔이 원점일 때만 활성인 것·하단 안내 줄에 담당자 조작과 그 결과(티칭·테스트 조작 포함), 작업의 진행·결과, HW 상태 전이, 시스템 연결 끊김·연결을 띄운 시각(메시지 timestamp 형식)과 함께 한 줄로 띄우고 새 안내가 앞 안내를 덮는 것

이 셋을 뺀 나머지는 모두 업체에서 결정하실 영역입니다.

## 1. 태블릿 UI 개요

태블릿은 AMMR 본체에 Mount되며, 항상 켜져 있고 설정 화면에 저장된 시스템 접속 계정으로 자동 접속된 상태에서 운영됩니다. 이 태블릿은 담당자가 현장에서 AMMR의 현재 상태를 확인하고 필요한 설정을 조정하기 위한 화면입니다.

이 문서에서는 다음 항목을 제안드립니다.

- 모든 화면 공통으로 항상 보여주셨으면 하는 AMMR 정보 (상단 고정 영역)
- 모든 화면 공통으로 항상 보여주셨으면 하는 조작·작업 결과·상태 변화 안내 (하단 안내 줄)
- 운영 중 화면 5종 (적재 상태 / 배정 상태 / 수동 조작 / 설정 / Log)
- 각 화면에 표시되었으면 하는 정보 항목
- 설정 화면의 입력 항목과 동작
- 참고용 UI 모형 5장 (화면별)

## 2. 권장 화면 구성

태블릿 화면은 **왼쪽 Sidebar + 표시 화면** 구조로 구성을 권장드립니다.

- **왼쪽 Sidebar**: 화면 전환 메뉴 (적재 상태 / 배정 상태 / 수동 조작 / 설정 / Log 5개 항목). 모든 화면에서 항상 표시되고, Sidebar 항목을 누르면 해당 화면으로 전환되는 동작이면 좋겠습니다.
- **운전 모드 전환**: 상단 고정 영역 왼쪽 끝 칸을 버튼 하나로 채워 그 버튼으로 자동·수동을 바꾸게 해 주시면 좋겠습니다. 현재 모드가 그 버튼에서 드러나면 되고, 크기·표기·버튼 형태는 업체 자유 결정 영역입니다. 다만 Pickup·Dropoff를 수행하는 동안(명령이든 티칭 조작이든, 도중 일시 정지와 그 뒤 원점 복귀 포함)에는 이 버튼을 비활성으로 두어 주시기를 부탁드립니다. 팔이 Unit을 문 채 멈추지 않게 하려는 것입니다. 모드를 바꾸면 화면도 함께 바꿔 주시면 좋겠습니다. 자동으로 바꾸면 적재 상태, 수동으로 바꾸면 수동 조작 화면입니다. 태블릿을 켰을 때도 그 모드에 맞는 화면으로 시작합니다.
- **수동 조작 화면**: 네 그룹으로 나눠 주시면 좋겠습니다. 위에서부터 안전 정지 해제 그룹, 원점 복귀 그룹, 작업 버튼 그룹, 티칭·테스트 조작 그룹입니다. 이 화면은 두 모드 모두에서 열리고, 그룹마다 활성 조건이 다릅니다 (아래 수동 조작 화면 참고).
- **상단 고정 영역**: 어느 화면에 있더라도 항상 같은 위치에 고정 표시되는 띠입니다. 왼쪽 칸 = 운전 모드 버튼 / 오른쪽 = 정보 칸 두 줄.
- **표시 화면**: Sidebar에서 선택된 화면이 표시되는 영역입니다.
- **하단 안내 줄**: 어느 화면에 있더라도 화면 맨 아래에 고정 표시되는 한 줄입니다. 담당자 조작, 시스템이 지시한 작업의 진행·결과, AMMR HW 상태 변화와 시스템 연결 끊김·연결을 띄웁니다 (아래 하단 안내 줄 참고).

수동 모드는 담당자가 AMMR을 직접 조작하는 모드입니다. 티칭·테스트 조작은 이 모드에서만 하시면 되고, 이 동안 AMMR은 스스로 움직이지 않습니다 — 저전력 자율 충전과 Job 대기 자체 충전 복귀가 멈추고, 시스템이 내린 작업 지시도 수행하지 않고 거부합니다. 자동에서 수동으로 바꾼 시점에 이동이나 충전 명령을 수행 중이었으면 그 작업을 실패로 알린 뒤 수동으로 들어갑니다. 집기나 놓기를 수행하는 동안에는 명령이든 티칭 조작이든 모드 버튼이 비활성이라 바꿀 수 없습니다. 보고는 그대로여서 수동 모드에서도 상태·Slot·위치·Battery 보고가 이어집니다.

운전 모드는 AMMR이 쥔 값이라 시스템 재접속 뒤에도 그대로 유지되고, AMMR은 그 보유값을 그대로 보고합니다. AMMR을 재시작하면 수동 모드로 시작하니, 자동 운영으로 돌리실 때는 운전 모드 버튼으로 바꿔 주시면 됩니다. 설정 화면 입력값이 재시작 후에도 유지된다는 안내는 설정 네 영역에 대한 것이라 이 값을 덮지 않습니다.

화면 디자인·색상·폰트·세부 배치는 업체 자유 결정 영역입니다.

**수동 조작 화면:**

담당자가 직접 하는 조작을 한 화면에 모았습니다. 버튼은 성격에 따라 그룹 박스로 나누고, 버튼마다 그 버튼이 하는 일을 라벨로 함께 달아 주시면 좋겠습니다. 버튼을 상단 고정 영역에서 이 화면으로 옮긴 것은 작은 태블릿에서 정보를 읽기 쉽게 하려는 것입니다.

※ 수동 조작 화면 그룹

| 그룹             | 버튼               | 활성 조건                                                                       | 라벨 예시                                        |
|------------------|--------------------|---------------------------------------------------------------------------------|--------------------------------------------------|
| 안전 정지 해제   | [Reset]            | 항상 (장애 중에는 로봇팔이 원점일 때만)                                         | 범퍼 충돌 일시 정지와 장애를 해제합니다          |
| 원점 복귀        | [역방향 원점 복귀] | 수동 모드이거나 장애 상태이고 로봇팔이 원점이 아닐 때                           | 움직여 온 경로를 거꾸로 따라 원점으로 돌아갑니다 |
| 원점 복귀        | [안전 원점 복귀]   | 수동 모드이거나 장애 상태이고 로봇팔이 원점이 아닐 때                           | 안전 위치를 거쳐 원점으로 간 뒤 Gripper를 엽니다 |
| 작업 버튼        | [작업 취소]        | 자동 모드에서 이동 명령 수행 중일 때만                                          | 이동 중인 작업을 확인 없이 바로 끊습니다         |
| 작업 버튼        | [최근 명령 재요청] | 시스템 연결 중·자동 모드·HW 상태 idle·charging·docked이고 최근 명령이 있을 때만 | 실패로 끝난 최근 명령을 다시 요청합니다          |
| 티칭·테스트 조작 | (업체 구성)        | 수동 모드일 때만                                                                | —                                                |

안전 정지 해제 그룹을 맨 위에 따로 둔 것은 AMMR이 멈췄을 때 [Reset] 버튼이 먼저 눈에 띄게 하려는 것입니다. 범퍼 충돌로 멈추거나 장애로 들어가면 이 화면으로 바꿔 주시면 좋겠습니다.

원점 복귀는 로봇팔을 기준 자세(원점)로 돌리는 버튼입니다. [역방향 원점 복귀]는 팔이 움직여 온 경로를 거꾸로 따라 돌아가며, Gripper를 닫았던 지점에서 열고 열려 있으면 그대로 둡니다. Unit을 물고 있었으면 집어 온 자리에 되돌려 놓습니다. [안전 원점 복귀]는 팔을 손으로 옮겨 지나온 경로를 따를 수 없을 때 안전 위치를 거쳐 돌아가고, 원점에 도착한 뒤 Gripper가 닫혀 있으면 엽니다. Unit을 물고 있었으면 원점에서 바로 꺼내시면 됩니다. 두 버튼은 수동 모드이거나 장애 상태이고 로봇팔이 원점이 아닐 때만 활성화됩니다. 시스템이 작업을 지시하지 않는 동안이라 지시와 겹치지 않고, 장애 중 스스로 충전 스테이션으로 가는 이동은 로봇팔이 원점에 있을 때만 일어나 이 버튼과도 겹치지 않습니다. 복귀하는 동안 HW 상태는 `manipulator_homing`으로 표시됩니다. 장애 상태에서 원점 복귀를 마쳐도 장애는 그대로입니다. 장애 중 로봇팔이 원점에 있지 않으면 [Reset]이 비활성이므로, 원점 복귀를 마친 뒤 [Reset]으로 해제하는 순서입니다.

티칭·테스트 조작 그룹의 구성, 라벨 문구, 그룹 안 배치는 업체 자유 결정 영역입니다.

범퍼 충돌로 일시 정지하거나 긴급정지 버튼이 눌리면 AMMR 자체 부저가 울립니다. 이때 담당자가 수동 조작 화면의 [Reset] 버튼을 누르면 정지가 해제됩니다. 범퍼 일시 정지는 해제된 뒤 수행 중이던 명령을 이어서 수행하고, 긴급정지는 그 명령을 실패로 회신합니다. 긴급정지를 비롯한 장애는 담당자가 현장을 조치한 뒤 [Reset]을 누르면 해제되며, 그 시점의 실제 상태(대기·충전 중·도킹)로 돌아갑니다. 설비 측 실패로 팔을 원점으로 되돌린 뒤 들어간 장애와 이동 명령의 수행 한도 초과로 들어간 장애는 자동 모드에서 장애를 유지한 채 스스로 충전 스테이션으로 가 충전하므로, 이때는 설비 앞이 아니라 충전 스테이션에서 AMMR을 찾으시면 됩니다. 이 이동 중에 [Reset]으로 해제하시면 가던 이동을 이어가며 자체 충전이나 저전력 상태가 됩니다. Safety Field 감지로 인한 일시 정지는 물체가 비켜나면 스스로 해제되므로 [Reset]을 누를 필요가 없습니다.

**작업 취소:**

이동 중인 작업을 끊어야 할 때 [작업 취소] 버튼을 누르시면 됩니다. 자동 모드에서 이동 명령을 수행하는 동안에만 활성화되고, 수동 모드의 티칭 이동이나 장애 중 충전 이동처럼 명령이 아닌 이동에서는 비활성입니다. 누르면 확인을 묻지 않고 바로 끊습니다.

그 작업의 Unit을 이미 싣고 있었으면 그 Unit이 실린 Slot 하나만 사용 보류로 두고 보관하던 적재 식별값을 비워 주시면 좋겠습니다. 그동안은 같은 작업이 다시 내려오지 않으므로, 되살리려면 설정 화면 적재 정보 관리에서 그 Slot에 Tray ID를 다시 넣고 [일괄 보고 재로드]를 눌러 주시면 됩니다. 아직 싣지 않은 상태였으면 Slot에 올릴 변화가 없어 작업 실패만 보고하면 됩니다.

**최근 명령 재요청:**

작업이 실패로 끝나면 담당자가 현장을 조치한 뒤 그 작업을 다시 요청할 수 있어야 합니다. [최근 명령 재요청] 버튼이 그 요청을 시스템에 보냅니다. 시스템은 이 AMMR에 마지막으로 내린 명령을 그대로 다시 내려 줍니다. 옮길 곳을 다시 정하지 않고 그때 값 그대로입니다.

조치하는 동안 AMMR이 제자리에 있다는 보장이 없으므로, 그 명령이 속한 이동부터 다시 내려옵니다. 집는 작업이 실패했으면 출발 설비로 이동한 뒤 집기부터, 놓는 작업이 실패했으면 도착 설비로 이동한 뒤 놓기부터, 이동이 실패했으면 그 이동부터입니다. AMMR 장애나 연결 끊김으로 시스템 쪽 Slot이 사용 보류로 잠겨 있을 수 있으므로, 이 버튼을 누르면 태블릿이 지금 상태를 먼저 한 번 올리고, 그 보고에 대한 시스템 응답을 받은 뒤 요청을 보냅니다. 그 보고로 잠금이 풀리고 적재·배정 화면도 함께 정정되므로 [일괄 보고 재로드]를 따로 누르지 않아도 됩니다.

버튼은 시스템 연결이 유효하고 자동 모드이며 HW 상태가 명령을 받을 수 있는 `idle`·`charging`·`docked`일 때만 활성화됩니다. 수동 모드에서는 시스템이 작업을 지시하지 않고, 그 밖의 HW 상태에서는 다시 내려온 명령을 AMMR이 수행하지 못하므로 비활성입니다.

누르면 다시 지시한 명령이나 거절이 올 때까지 다시 누를 수 없게 잠가 주시면 좋겠습니다. 누른 뒤 일괄 보고 응답, 시스템 수신 확인, 재지시 명령을 차례로 각각 응답 대기 한도(설정 화면·초기값 3초)만큼 기다리고, 어느 하나라도 오지 않으면 거기서 멈추고 잠금을 해제합니다. 재지시 명령은 이 요청에 답해 다시 내려온 명령을 말하며, 누를 때 보낸 명령 번호가 함께 실려 오므로(`resume_job_id`) 그 번호로 가려 주시면 됩니다. 시스템이 다시 내리지 않기로 하면 재지시 명령 대신 같은 번호가 실린 거절이 사유 코드(`reason`)와 함께 오므로, 그때는 더 기다리지 않고 잠금을 해제합니다. 기다리는 동안 이 번호가 없는 다른 명령이 오면 AMMR이 수행하지 않고 거부합니다(`ammr_hw_resume_pending`). 이 거부는 하단 안내 줄에 띄우지 않습니다. 일괄 보고 응답이 오지 않으면 요청을 보내지 않습니다. 진행 단계와 실패는 하단 안내 줄에 띄웁니다. 잠긴 동안임을 어떻게 보이게 할지(배경색·흐리게 등)는 업체 자유 결정 영역입니다.

장애나 연결 끊김으로 결과가 전달되지 못한 채 끝난 명령은 실패한 명령과 같이 다시 내려옵니다. 명령 이력이 없거나 마지막 명령이 아직 끝나지 않았거나 성공으로 끝났거나 충전 명령이었거나, 그 작업을 이미 다른 AMMR이 이어받아 옮기는 중이거나, 싣고 있던 Slot의 적재 정보가 비어 있으면(작업 취소 뒤 Tray ID를 다시 넣지 않은 경우 등) 시스템이 다시 내리지 않습니다. 이때는 확인 뒤에 새 명령 대신 거절이 사유 코드와 함께 와서 하단 안내 줄에 재지시 명령 없음과 그 사유 코드가 뜹니다. 다시 내려온 명령을 AMMR이 수행하다 또 실패하면 그 사유가 작업 실패로 시스템에 회신되고, 하단 안내 줄에도 그대로 드러납니다.

**하단 안내 줄:**

담당자가 태블릿에서 한 조작, 시스템이 지시한 작업(Job)의 진행과 결과, AMMR HW 상태가 바뀐 사건, 시스템 연결이 끊기거나 다시 붙은 사건을 한 줄로 띄워 주시면 좋겠습니다. HW 상태 전이는 운전 모드와 상관없이 모두 띄우며, 장애로 들어간 경우도 여기에 들어갑니다. 작업이 도중에 멈춰 AMMR이 팔을 원점으로 되돌리는 경우도 그 작업의 마무리라, 복귀를 마치거나 실패하면 그 결과를 띄웁니다. 티칭·테스트 조작은 업체가 구성하시는 영역이라, 어떤 조작이든 현장 담당자가 결과를 알 수 있게 그 조작이 끝났는지, 멈췄는지(수행 한도에 걸려 멈춘 경우 포함), 실패했는지와 그 이유를 띄워 주시면 좋겠습니다. 문구는 업체 자유 결정 영역입니다. 안내 앞에 그 안내를 띄운 시각을 메시지 timestamp와 같은 형식(`YYYY-MM-DD HH:MM:SS.mmm`)으로 붙이고, 새 안내가 앞 안내를 덮습니다. 시스템 기록과 같은 형식이라 맞대 보기 쉽습니다. 따로 지우지 않고 다음 안내가 올 때까지 둡니다. 이 줄은 최신 한 줄만 보이므로 지난 안내는 Log 화면에서 확인합니다. Slot 상태 전이와 재요청 중 받은 다른 명령의 거부는 이 줄에 넣지 않고 Log 화면에만 남깁니다. Slot 상태는 적재 상태 화면이 보여 주고, 재요청 중 거부는 진행 안내를 덮지 않게 하려는 것입니다.

작업 실패 사유 코드와 HW 상태 전이 사유 코드(`reason`)는 AMMR이 보낸 값만 가공 없이 그대로 띄워 주시기를 부탁드립니다. 한글 뜻은 붙이지 않습니다. 작은 화면에서 한 줄을 짧게 유지하고, 현장 작업자가 본 그대로 개발자에게 전달하면 시스템 기록과 바로 맞대 볼 수 있기 때문입니다. 문구 표현은 업체 자유 결정 영역입니다.

## 3. 상단 고정 영역 (모든 화면 공통, 항상 고정 표시)

다음 9개 항목이 어느 화면에서나 보이도록 구성해 주시면 좋겠습니다. 오른쪽 정보 칸은 두 줄로 나누어, 첫 줄에 시스템 연결·Battery·HW 상태·진행 한도·위치를, 둘째 줄에 최근 명령·설비 Slot·AMMR Slot을 두시면 좋겠습니다. 첫 줄은 AMMR이 스스로 아는 값이라 시스템 연결이 끊겨도 그대로 차 있고, 둘째 줄은 시스템이 명령에 담아 주는 값이라 끊기면 함께 빕니다. 줄을 그 경계에 맞추면 단절 시 둘째 줄이 통째로 비어 한눈에 드러납니다. 운전 모드 버튼은 왼쪽 칸을 채우고, 나머지는 모두 읽기만 하는 정보 칸입니다. 누르는 버튼은 수동 조작 화면에 모아 상단은 정보를 읽는 데만 씁니다. 표기 형식은 업체 자유 결정 영역입니다.

※ 상단 고정 영역 항목

| 항목        | 내용 |
|-------------|---|
| 운전 모드   | 자동·수동을 바꾸는 버튼 하나. 현재 모드가 이 버튼에서 드러나면 됩니다 |
| 시스템 연결 | 시스템과의 연결 상태 표시 (연결·해제 버튼은 설정 화면 시스템 접속 영역) |
| Battery     | 현재 충전량 (%) |
| HW 상태     | AMMR이 보고하는 현재 상태 |
| 진행 한도   | 현재 동작에 걸린 한도의 남은 시간 (예: `Move TimeOut : 4m 32s`) |
| 위치        | 현재 Node ID와 현재 위치 좌표(x, y·m)·방향각(a·도) (예: `WIP-CLN001 · 12.4, 8.7, 90°`) |
| 최근 명령   | 시스템이 마지막으로 지시한 명령 (job_type) |
| 설비 Slot   | 최근 명령이 다루는 외부 설비 Slot ID (예: `CNC-RAC-A02-BEFORE`) — Pickup=집어 오는 자리 / Dropoff=놓는 자리 / Move=뒤따를 Job의 예정 자리(참고용) / Charge=해당 없음. 해당 없거나 값을 못 받는 동안은 빈값(예: `-`) |
| AMMR Slot   | 최근 명령이 다루는 이 AMMR의 Slot 번호(1~6) — Pickup=적재 대상 / Dropoff=하역 대상 / Move=뒤따를 Job의 예정 Slot(참고용) / Charge=해당 없음. 해당 없거나 값을 못 받는 동안은 빈값(예: `-`) |

각 항목의 구체 표기 형식·기호·아이콘은 업체 자유 결정 영역입니다. 내용이 식별 가능한 형태로만 구성되면 됩니다. 단, HW 상태·최근 명령 값과 위치 칸의 현재 Node ID·좌표·방향각은 값을 가공 없이 그대로 표시해 주시면 좋겠습니다. 아래 표기 값 안내를 참고해 주세요.

**HW 상태·최근 명령 표기 값:**

HW 상태는 AMMR이 자체 보고하는 물리 상태이고, 최근 명령은 시스템이 마지막으로 지시한 Job 명령입니다.

| 항목      | 표기 값 |
|-----------|---|
| HW 상태   | `move` / `pickup` / `dropoff` / `charge` / `manipulator_homing` / `idle` / `charging` / `docked` / `low_battery` / `self_charge` / `paused` / `error` (AMMR 자체 보고 hw_state 값) |
| 최근 명령 | `move` / `pickup` / `dropoff` / `charge` (시스템이 지시한 job_type) |

HW 상태·최근 명령 두 칸은 문서 안내의 고정 항목입니다. AMMR이 보고한 hw_state 값과 시스템이 지시한 job_type 값을 가공·번역 없이 그대로 표시해 주시기를 부탁드립니다. 위치 칸의 현재 Node ID(node_id)도 AMMR이 보고한 값을 그대로 표시해 주시면 좋겠습니다. AMMR이 어느 Node에도 있지 않은 동안(Node 사이를 지나는 중)에는 이 값이 비어 오므로, 그때는 빈값으로 표시해 주시면 좋겠습니다. 시스템이 수신한 값과 화면 표시가 일치해야 현장에서 문제가 생겼을 때 원인을 짚을 수 있습니다.

HW 상태는 AMMR의 현재 물리 동작이고 최근 명령은 시스템이 마지막으로 지시한 명령이라 서로 다를 수 있어 두 값을 따로 표시합니다 (명령 이후 완료·전이하면 HW 상태만 바뀝니다).

**최근 명령·Slot 갱신 시점:** 이 세 값은 Core가 새 Job 지시를 보낼 때 갱신되며, 명령이 완료·전이해도 다음 명령 전까지 마지막 값을 유지합니다 (HW 상태는 실시간, 최근 명령은 명령 단위 갱신). 다만 수행에 진입하지 않고 거부한 지시는 갱신하지 않고 이전 값을 그대로 두시면 좋겠습니다. 명령 이력이 없거나 시스템 연결이 끊긴 동안에는 빈값으로 표시됩니다. Move 지시에 실려 오는 Slot은 뒤따를 Pickup·Dropoff에서 다룰 예정 값이므로 참고용으로만 보시면 되고, 실제로 다룰 Slot은 뒤따르는 지시가 쥡니다. 설비 Slot ID는 설비 ID로 시작하므로 이 값 하나로 어느 설비의 어느 자리인지가 함께 읽힙니다.

**진행 한도 표기 값:**

현재 AMMR이 어떤 동작에 걸려 있는지에 따라 표시 대상이 달라집니다. 남은 시간을 보여주시면 담당자가 언제 실패로 넘어가는지 가늠할 수 있습니다.

| 표시 조건                                       | 표시할 한도                                      |
|-------------------------------------------------|--------------------------------------------------|
| `move` (두 모드 · 티칭 이동 포함)               | Move 수행 한도 남은 시간                         |
| `pickup` / `dropoff` (두 모드 · 티칭 조작 포함) | Pickup·Dropoff 수행 한도 남은 시간               |
| Pickup·Dropoff 중 설비 Interlock 대기           | 설비 Interlock 대기 한도 남은 시간               |
| `idle` (자동 모드)                              | Job 대기 한도 남은 시간 (자체 충전 진입까지)     |
| `error` 중 자율 충전 이동 갈래 (자동 모드)      | Job 대기 한도 남은 시간 (충전 스테이션 이동까지) |
| MQTT 연결 끊김                                  | Broker 재연결 한도 남은 시간                     |
| 그 밖                                           | 표시 없음 (빈값)                                 |

위 조건은 함께 설 수 있습니다. Pickup·Dropoff 중 설비 Interlock을 기다리는 동안이나 명령을 수행하는 중에 시스템 연결이 끊긴 동안에는 한도가 둘 이상 함께 흐르며, 각 한도는 따로 셉니다. 이때는 가장 먼저 끝나는 한도 하나의 남은 시간을 보여 주시면 좋겠습니다. 담당자가 다음에 무엇이 멈추는지를 놓치지 않게 하려는 것이고, 연결 끊김은 연결 상태 표시와 하단 안내 줄이 따로 보여 줍니다. 라벨 문구·시간 표기 형식은 업체 자유 결정 영역입니다.

이 값은 AMMR이 자기 설정값과 자기 동작 시각으로 계산하는 화면 표시용 값이라 시스템과 주고받지 않습니다.

**시스템 연결 상태 표시:**

상단 고정 영역에는 연결 상태만 표시해 주시면 좋겠습니다. 연결 중일 때와 끊김 상태일 때를 구분할 수 있는 시각 표시(예: 색상·아이콘·기호 등)면 되고, 구체 표기는 업체 자유 결정 영역입니다. 연결·해제 버튼은 설정 화면 시스템 접속 영역에 둡니다.

MQTT 연결이 끊기면 AMMR이 1초 간격으로 자동 재연결을 시도합니다. 설정 화면의 Broker 재연결 한도(초기값 300초)가 지나도록 회복되지 않으면 자동 시도를 멈추므로, 그 뒤에는 담당자가 설정 화면의 [연결] 버튼으로 직접 연결하게 됩니다.

담당자가 티칭·테스트 조작으로 AMMR을 직접 움직이실 때는 상단 고정 영역 왼쪽 끝 버튼으로 운전 모드를 수동으로 바꾸신 뒤 하시면 됩니다. 수동 모드에서는 시스템이 이 AMMR에 작업을 지시하지 않고, 지시가 오더라도 AMMR이 수행하지 않습니다.

'시스템 연결' 상태 판정에는 AMMR과 함께 쓰는 MQTT 연결뿐 아니라 시스템(Core) 측 연결 상태도 반영합니다. 그 MQTT 연결이 살아 있어도 시스템(Core)이 다운되면 시스템 권위 값(최근 명령·설비 Slot·AMMR Slot·Slot의 Unit 정보·배정)을 받을 수 없으므로 '시스템 연결 끊김'으로 표시합니다. 시스템은 자신의 연결 상태를 알리는 메시지를 발행하며, 태블릿은 이를 구독해 시스템 다운을 인지합니다 (수신 방식·메시지는 "Core ↔ 물류 AMMR Interface Control Document"를 따릅니다). 표시가 이렇게 두 축을 함께 보는 것과 달리 연결/해제 버튼이 다루는 대상은 MQTT 연결 하나이므로, 시스템(Core)만 다운된 구간에서는 끊김으로 표시되면서도 MQTT 연결은 살아 있습니다.

**시스템 연결이 끊긴 동안의 표시 방식:**

이 문서에서 다루는 표시값은 출처에 따라 권위가 둘로 나뉩니다 — AMMR/태블릿 자체 값(HW 상태·위치·Battery·slot_state 등 AMMR·태블릿 권위)과 Core가 명령에 담아 내려주는 값(최근 명령·설비 Slot·AMMR Slot·Slot의 Unit 정보·배정 상태 화면의 표시값 등 시스템 권위). 시스템 연결이 끊긴 동안에는 두 권위 출처에 따라 표시 방식이 달라집니다. AMMR 권위 값은 시스템 연결과 무관하게 마지막 수신값을 그대로 유지하고, 시스템 권위 값은 시스템의 판단이 필요한 값이므로 빈값으로 표시됩니다. 이 일반 원칙은 이 문서의 적재 상태·배정 상태 화면 표시값에 동일하게 적용됩니다. 시스템 연결이 회복되면 시스템 권위 값은 태블릿이 보유한 값으로 표시를 되살리고, Core 확정 배정과 어긋난 Slot은 일괄보고 응답으로 정정됩니다.

이 상단 고정 영역에서의 항목별 적용은 다음과 같습니다.

- **HW 상태·위치·Battery**: AMMR 자체에서 보고되는 값이므로 마지막 수신값을 그대로 유지합니다.
- **최근 명령·설비 Slot·AMMR Slot**: Core가 명령에 담아 주는 값이므로 빈값으로 표시합니다 (예: 항목 칸을 빈 텍스트로 두거나 `-`·회색 계열로 표시).

시스템 연결 항목의 끊김 표시(예: ○)가 단절 상태를 표면화하는 역할을 합니다. 단절 상태에서 다른 항목 값에 별도의 시각 구분(예: 흐리게·기호 부착 등)을 추가하실지 여부는 업체 자유 결정 영역입니다.

**표시값 갱신 규칙 (모든 화면 공통):**

표시값은 출처에 따라 갱신 주체·시점이 셋으로 나뉩니다.

| 축                          | 값                                                                         | 갱신 시점                                                                  | 시스템 연결 끊김 시                   |
|-----------------------------|----------------------------------------------------------------------------|----------------------------------------------------------------------------|---------------------------------------|
| 태블릿·HW 자체 판정         | slot_state(점유·미점유·사용 보류·작업 실패)·HW 상태·위치·Battery·진행 한도 | 실시간 (Sensor·HW 변화 즉시)                                               | 계속 판정·표시                        |
| 태블릿이 명령 수신으로 표기 | 최근 명령·설비 Slot·AMMR Slot                                              | Job 지시 수신 시 (다음 명령 전까지 마지막 값 유지·거부한 지시는 갱신 없음) | 빈값                                  |
| Core 명령 담긴 값           | Unit 라벨·모델·버전·Tray·수량·용도·출발/도착                               | Core 메시지 수신 시 (Job 지시 + 정합 응답)                                 | 빈값 (Slot 번호 등 화면 틀 값은 유지) |

담당자가 별도 새로고침 동작을 하지 않아도 위 규칙으로 자동 갱신됩니다.

## 4. 적재 상태 화면

AMMR의 6 Slot 각각의 현재 적재 상태(slot_state·Unit 정보)를 격자 형태로 보여주는 화면입니다. Slot당 한 칸의 셀이며, 각 셀에는 다음 정보가 함께 표시됩니다.

※ Slot 셀 표시 정보

| 항목      | 내용 |
|-----------|---|
| Sensor    | HW Slot Sensor의 점유 여부 (`●` 점유 / `○` 미점유) |
| Slot 번호 | 1~6 |
| Slot 상태 | 태블릿이 자체 판정한 `slot_state` — `occupied`(점유)/`empty`(미점유)/`blocked`(사용 보류)/`job_failed`(작업 실패) |
| 정보      | Slot에 적재된 Unit 라벨(`투입코드_유닛번호`). 비어 있을 때는 비어 있음을 알 수 있는 표기 |

각 항목의 표기 방법은 업체 자유 결정 영역입니다. 예를 들어 slot_state의 `occupied`·`empty`는 Sensor 표기(`●/○`·`ON/OFF`·아이콘 등), 비어 있음은 `(비어 있음)`·`Empty`·`--` 등 내용이 통하는 어떤 형태로든 표시 가능합니다.

**slot_state 표기 방식:**

Sensor는 HW Sensor 원값을, Slot 상태는 태블릿이 판정한 `slot_state`를 표시합니다. `occupied`·`empty`는 Sensor와 같은 기호로 두시고, `blocked`(사용 보류)·`job_failed`(작업 실패)는 정상 상태와 한눈에 구분되게 표시해 주시면 좋겠습니다(빨강 계열 권장). 구체 표기와 보조 시각 표시(아이콘 등)는 업체 자유 결정 영역입니다.

**`blocked`(사용 보류)의 의미:**

slot_state가 `blocked`라는 것은 태블릿이 해당 Slot을 사용 보류로 판정했다는 의미입니다. 예를 들어 Sensor는 점유로 잡혀 있는데 식별된 Unit 정보가 없는 경우(사람이 임의로 Unit을 올려놓았으나 시스템이 지시하지 않은 상황 등)에 발생합니다. 이 경우 Sensor는 점유(●)이지만 사용 보류로 구분 표기되고 정보 칸은 비어 있음을 나타냅니다. `job_failed`는 Job 실패로 해당 Slot이 이상 상태가 된 경우이며 마찬가지로 구분 표기됩니다.

**Unit 라벨과 스티커:**

Unit 라벨은 `투입코드_유닛번호` 형태로 표시됩니다. 예시는 `26SF03002001_001`입니다. 투입코드 부분은 시스템이 외부로부터 받은 투입 단위 코드이고, 언더바 뒤는 해당 투입코드 안에서 부여된 Unit 일련번호입니다.

공정 Tray에는 사람이 눈으로 대조할 수 있는 라벨과 시스템이 기계 입력으로 받을 수 있는 QR 코드가 함께 부착된 스티커가 붙어 있고, 되담기를 마친 적층 Tray에는 스티커 없이 QR이 각인돼 있습니다. 라벨에는 이 식별값(`투입코드_유닛번호`)이 사람이 읽을 수 있는 형태로 적혀 있고, QR 코드에는 그 Tray의 시스템 권위 식별값인 Tray ID(UUID)가 인코딩되어 있습니다. 라벨은 Unit 단위 표기이고 QR은 Tray 단위 식별값이라 서로 다른 값입니다.

이 화면에 표시되는 식별값은 담당자가 현장에서 공정 Tray 스티커의 라벨과 직접 대조해 확인하기 위한 정보입니다. Tray ID는 적재 정보를 수동으로 입력해야 하는 경우 설정 화면의 적재 정보 관리 영역에서 사용되며, 자세한 동작은 이 문서 뒤쪽 설정 화면과 적재 정보 재로드 동작 안내 부분을 참고해 주세요.

**시스템 연결이 끊긴 동안의 표시 방식:**

표시값은 권위 출처에 따라 단절 동안 표시 방식이 달라집니다.

- **Sensor**: HW Sensor 값이므로 단절 동안에도 그대로 표시합니다.
- **Slot 번호**: 각 셀이 몇 번 Slot인지 가리키는 자리 이름이므로 항상 표시됩니다.
- **Slot 상태(slot_state)**: 태블릿이 자체 판정하는 값이므로 단절 동안에도 계속 판정·표시합니다.
- **정보(Unit 라벨)**: Core가 명령에 담아 주는 값이므로 단절 동안 빈값으로 표시합니다.

**갱신 방식:**

slot_state는 태블릿이 자체 판정으로, Unit 정보는 Core가 명령에 담아 준 값으로 자동 갱신됩니다. 담당자가 별도 새로고침 동작을 하지 않아도 됩니다.

## 5. 배정 상태 화면

각 Slot에 매칭된 Job 정보를 보여주는 화면입니다. 6 Slot 모두 항목으로 표시되며, Job이 배정되어 있지 않거나 Slot이 비어 있는 경우 또는 사용 보류(blocked)·작업 실패(job_failed) 상태인 경우에는 그 상태를 알 수 있는 표기로 표시됩니다.

※ Slot별 표시 정보 (Job이 배정된 Slot에 한함)

| 항목      | 내용 |
|-----------|---|
| Unit 라벨 | 해당 Slot에 적재된 Unit 라벨 (적재 상태 화면과 동일 형식 `투입코드_유닛번호`) |
| 모델      | Unit에 담긴 제품의 모델 코드 |
| 버전      | 모델의 버전 표기 |
| Tray 종류 | Unit의 Tray 종류 (공정 Tray·적층 Tray) |
| Tray 단   | Unit을 구성하는 Tray 단 수 |
| 수량      | Unit 안 제품 개수 |
| 용도      | Unit에 담긴 제품의 용도 (Core 제공 값 그대로) |
| 출발지    | 이 Unit이 출발한 공정·설비 — 시스템이 명령에 담아 준 출발 설비 ID를 그대로 표시 (예: `WIP-CLN001`) |
| 도착지    | 이 Unit이 갈 다음 공정·설비 — 시스템이 명령에 담아 준 도착 설비 ID를 그대로 표시 (예: `CNC-RAC-A02`) |

표기 형식·배치는 업체 자유 결정 영역입니다.

**비어 있는 Slot · Job 미배정 Slot · 사용 보류(blocked)의 표기:**

비어 있는 Slot은 비어 있음을 알 수 있는 표기(예: `(비어 있음)`), 시스템 권위 정보를 아직 받지 못한 Slot은 작업 배정 대기를 알 수 있는 표기(예: `(작업 배정 대기)`), 사용 보류(`blocked`)·작업 실패(`job_failed`)는 그 상태를 알 수 있는 빨강 표기(예: `(사용 보류)`·`(작업 실패)`)가 권장됩니다.

작업 배정 대기 상태는 Slot의 시스템 권위 정보가 아직 도착하지 않아 그 값 일체가 빈값으로 표시될 때 나타나며, 시스템 연결이 끊긴 동안이 그 대표적인 경우입니다.

**시스템 연결이 끊긴 동안의 표시 방식:**

이 화면의 표시값(Unit 라벨·모델·버전·Tray·수량·용도·출발·도착) 일체는 모두 Core가 명령에 담아 주는 값이므로, 시스템 연결이 끊긴 동안에는 Slot 번호 외 표시값이 모두 빈값으로 표시됩니다. 빈 칸은 작업 배정 대기 표기로 두어도 좋습니다. 다만 Slot 상태(slot_state)는 태블릿이 자체 판정하는 값이므로 단절 동안에도 계속 판정·표시합니다.

**우선순위 표기에 대하여:**

Job의 우선순위는 시스템 측이 판단합니다. 우선순위는 어느 Unit을 먼저 옮길지 고르는 순서이고, 그 Job이 쓸 Slot은 시스템이 함께 정해 명령에 담아 줍니다. 이 화면은 순번이 아니라 Slot 번호 기준으로 표시되며, 별도의 우선순위 번호는 표시하지 않습니다.

**갱신 방식:**

이 화면의 모든 정보 역시 Core가 명령에 담아 준 값으로 자동 갱신됩니다.

## 6. 설정 화면

설정 화면은 다음 4개 영역으로 구성됩니다 — **시스템 접속**, **Battery·충전 운영**, **Job 수행 한도**, **적재 정보 관리**.

네 영역 모두 같은 편집 방식을 씁니다. 평소에는 입력 항목이 잠겨 있고, [편집] 버튼을 누른 뒤에만 값을 고칠 수 있으며, [저장] 버튼으로 확정합니다. [편집]은 시스템 연결이 끊긴 상태에서만 활성화됩니다 (정상 운영 중에는 이 값들이 그대로 동작에 쓰이고 있어 손입력이 오기입이 되기 때문입니다).

- **시스템 접속 영역**: [편집] → 입력 → [저장]으로 AMMR에 반영됩니다.
- **Battery·충전 운영 영역**: [편집] → 입력 → [저장]으로 AMMR에 반영됩니다.
- **Job 수행 한도 영역**: [편집] → 입력 → [저장]으로 AMMR에 반영됩니다.
- **적재 정보 관리 영역**: [편집] → Slot별 입력 → [저장]으로 AMMR 내부에 확정되고, 시스템 전달은 재연결 후 [일괄 보고 재로드] 또는 다음 일괄 보고가 맡습니다.

이 화면 4개 영역의 입력 값은 모두 AMMR 내부에 저장되어 AMMR 재시작 후에도 유지됩니다. 다만 적재 정보 관리 영역의 Slot 저장 입력값은 재시작 시 Sensor가 미점유로 판별된 Slot에 한해 비워집니다(아래 적재 정보 관리 참고).

Battery 임계치와 보고 주기 항목은 소수 입력을 받을 수 있게 해 주시면 좋겠습니다 (예: 위치 보고 주기 0.5초).

각 영역의 버튼 명칭·형태·배치는 업체 자유 결정 영역입니다.

### 6.1 시스템 접속

※ 시스템 접속 입력 항목

| 항목               | 초기값 | 비고 |
|--------------------|--------|---|
| 시스템 Host IP     | -      | AMMR이 시스템 측 MQTT Broker에 접속할 IP 주소 |
| 시스템 포트        | -      | 시스템 측 MQTT Broker 접속 포트 번호 |
| MQTT 접속 ID       | -      | 시스템 측 MQTT Broker 접속 자격증명 |
| MQTT 접속 비밀번호 | -      | 시스템 측 MQTT Broker 접속 자격증명 |
| 일괄 보고 주기     | 60초   | AMMR이 운영 상태값 전체를 주기적으로 자동 보고하는 간격 |
| 위치 보고 주기     | 1초    | AMMR이 위치(현재 Node ID·좌표·방향각)를 자동 보고하는 간격 |
| BMS 보고 주기      | 10초   | AMMR이 BMS 정보를 자동 보고하는 간격 |
| Broker 재연결 한도 | 300초  | 연결이 끊겼을 때 1초 간격 자동 재연결을 이어가는 한도 |
| 응답 대기 한도     | 3초    | [일괄 보고 재로드]·[최근 명령 재요청]이 시스템 응답·수신 확인·재지시 명령을 각각 기다리는 한도 |

이 영역 항목은 시스템 연결이 끊긴 상태에서 [편집]을 누르신 뒤 변경할 수 있고, 입력하신 값은 [저장] 버튼으로 일괄 적용됩니다.

이 영역의 [편집]·[저장] 아래에 시스템 연결 버튼을 폭 넓은 버튼 하나로 두어 주시면 좋겠습니다. 연결되어 있으면 [해제], 끊겨 있으면 [연결]로 바뀌는 한 버튼입니다. AMMR에 장애·오류가 생겼을 때 담당자가 연결을 끊고 조치한 뒤 다시 연결할 수 있어야 하기 때문입니다. [편집]으로 입력이 열려 있는 동안에는 이 버튼도 비활성화해 주시면 좋겠습니다. 입력 도중 연결되면 고치던 값이 저장 전 상태로 동작에 쓰이기 때문입니다.

MQTT 연결이 끊기면 AMMR이 1초 간격으로 자동 재연결을 시도하고, Broker 재연결 한도가 지나도록 회복되지 않으면 자동 시도를 멈춥니다. 그 뒤에는 이 영역의 [연결] 버튼으로 담당자가 직접 연결해 주셔야 합니다.

### 6.2 Battery·충전 운영

※ Battery·충전 운영 입력 항목

| 항목                     | 초기값 | 비고                                                                            |
|--------------------------|--------|---------------------------------------------------------------------------------|
| 충전 스테이션 번호       | -      | AMMR이 충전 시 이동할 스테이션 번호 (자율 충전·자체 충전·시스템 충전 지시 공통) |
| Battery 충전 종료 임계치 | 80%    | AMMR이 충전을 끊고 도킹한 채 머무는 기준값                                      |
| Battery 재충전 임계치    | 70%    | 도킹한 채 이 값 이하로 내려가면 충전을 다시 시작하는 기준값                     |
| Battery 저전력 임계치    | 20%    | AMMR이 자율 충전 진입을 판단하는 값                                             |
| Job 대기 한도            | 10초   | 새 Job 지시 없이 이 시간이 지나면 충전 스테이션으로 자율 복귀                   |

충전 스테이션 번호는 문자열로 입력받습니다 (지금은 숫자 형태이나 향후 다른 식별자 형태가 될 수 있습니다. 예: `1`, `2`, `3`).

**이 영역 안내 문구 (화면에 함께 표시):**

> 충전 스테이션 번호는 AMMR이 충전 시 이동할 스테이션 위치이고(자율 충전과 자체 충전, 시스템의 충전 지시 모두 이 스테이션을 사용합니다), Battery 충전 종료·재충전·저전력 임계치는 AMMR이 지정된 충전 스테이션으로 스스로 충전·복귀 동작을 결정하는 기준값입니다. 초기값은 각각 80%·70%·20%입니다. 현장 상황에 맞게 변경하실 수 있으며, 값을 고치려면 시스템 연결을 해제하신 뒤 [편집]을 누르시고 [저장] 버튼을 누르신 시점에 적용됩니다. 또한 Job 대기 한도는 새 Job 지시 없이 대기가 이어질 때 AMMR이 충전 스테이션으로 스스로 돌아가는 기준입니다. 초기값은 10초이며 Battery 잔량과 무관하게 동작합니다. 복귀 중에는 시스템이 Job을 지시하지 않으며, 도킹한 뒤 지시를 받으면 충전 중이면 충전을 멈추고 그 Job을 수행합니다.

### 6.3 Job 수행 한도

이 영역은 AMMR이 Job 동작을 얼마나 오래 끌 수 있는지, 설비 신호를 얼마나 기다릴지를 정하는 값입니다.

※ Job 수행 한도 입력 항목

| 항목                     | 초기값 | 비고                                       |
|--------------------------|--------|--------------------------------------------|
| Move 수행 한도           | 300초  | Move Job 동작을 마쳐야 하는 한도           |
| Pickup·Dropoff 수행 한도 | 300초  | Pickup·Dropoff Job 동작을 마쳐야 하는 한도 |
| 설비 Interlock 대기 한도 | 180초  | 설비 Interlock 신호 확보를 기다리는 한도   |

**이 영역 안내 문구 (화면에 함께 표시):**

> Move·Pickup·Dropoff 수행 한도를 넘기면 AMMR은 그 Job을 중단하고 장애로 들어가 시스템에 실패를 알립니다. 이동 명령이었으면 장애를 유지한 채, 자동 모드에서 Job 대기 한도가 지나면 충전 스테이션으로 가서 충전하고, 집기·놓기 명령이었으면 팔이 뻗은 채 그 자리에 멈춥니다. 담당자가 현장을 확인하신 뒤, 팔이 원점에 있지 않으면 수동 조작 화면의 원점 복귀 버튼으로 먼저 팔을 돌리시고 [Reset]으로 해제해 주시면 시스템의 사용 보류도 함께 풀립니다. 설비 Interlock 대기 한도는 CNC WIP과 주고받는 동작 겹침 방지 신호를 기다리는 한도이며, 이 한도를 넘기면 AMMR은 팔을 원점으로 되돌린 뒤 장애로 들어가고, 자동 모드에서 Job 대기 한도가 지나면 충전 스테이션으로 갑니다. 해제는 위와 같습니다(이 갈래는 팔이 이미 원점이라 바로 [Reset]입니다). 담당자가 직접 조작해 수행한 동작에도 같은 한도가 걸리며, 이때는 알릴 Job이 없어 AMMR이 수행만 중단하고 멈춘 사실을 하단 안내 줄에 띄웁니다. 값을 고치려면 시스템 연결을 해제하신 뒤 [편집]을 누르시고 [저장] 버튼을 누르신 시점에 적용됩니다.

### 6.4 적재 정보 관리

이 영역은 **Slot별 Unit 정보 입력 박스 6개 + Slot별 [초기화] 버튼 6개**와 **일괄 보고 재로드 버튼 1개**로 구성해 주시면 좋겠습니다.

이 영역은 시스템 연결이 끊긴 동안 담당자가 Slot별 적재 정보를 수동으로 입력해 두고, 시스템 재연결 후 [일괄 보고 재로드] 버튼으로 일괄 전달해 사용 보류(blocked)를 풀기 위한 영역입니다. 정상 운영(시스템 연결 유효 + AMMR Job 수행) 중에는 시스템이 명령에 담아 Slot의 적재 정보를 채우므로, 이 영역에 담당자가 별도로 개입할 필요가 없습니다 (자세한 동작은 이 문서 뒤쪽 적재 정보 재로드 동작 안내 부분을 참고해 주세요).

**Slot별 Unit 정보 입력 박스:**

- Slot 1~6 각각에 텍스트 입력 박스를 1개씩 배치해 주시면 좋겠습니다.
- 이 입력 박스에 들어가는 값은 **Unit ID 또는 Tray ID** (둘 다 시스템 권위 식별값·UUID)입니다. 담당자가 직접 넣는 값은 언제나 Tray ID입니다. 실물에서 읽을 수 있는 값이 Tray QR뿐이기 때문입니다. 시스템이 채워 넣는 기본값은 Unit ID입니다. 시스템은 Tray ID를 받으면 그 Tray가 속한 Unit을 판정하므로 어느 쪽이 들어와도 됩니다. 두 값 모두 적재 상태 화면에 표시되는 `투입코드_유닛번호` 라벨과는 별도의 값입니다. 라벨은 담당자가 Slot의 Unit을 눈으로 식별하기 위한 사람 읽기용 표기이고, 이 입력 박스 값은 시스템이 적재 Unit을 권위적으로 인지하기 위한 시스템 입력용 식별값입니다.
- 적재된 Slot의 입력 박스에는 마지막 시스템 응답 또는 [일괄 보고 재로드] 시점의 Unit ID가 기본값으로 표시됩니다. 이 값은 AMMR 내부에 저장되어 재시작 후에도 유지되며(재시작 시 Sensor 판별에서 미점유로 나온 Slot은 저장값을 비웁니다. 아래 규칙 참고), 정상 운영 중 명령 선탑재 값으로 갱신되는 곳에는 갱신값으로 덮어 씌워집니다. 비어 있는 Slot의 입력 박스는 빈 상태로 표시됩니다.
- 입력 박스를 터치하면 활성화되어 가상 키보드가 표시되고, 담당자가 직접 값을 입력할 수 있습니다.
- 향후 QR 리딩을 통한 입력도 지원되도록 구성해 주시면 좋겠습니다 (Tray의 QR 코드를 스캐너로 읽어 해당 Slot의 입력 박스 값으로 채워 넣는 방식. QR 코드에는 그 Tray의 Tray ID(UUID)가 인코딩되어 있습니다).

**Slot별 [초기화] 버튼:**

- 각 Slot 입력 박스 우측에 [초기화] 버튼을 1개씩 배치해 주시면 좋겠습니다.
- 이 버튼은 해당 Slot 입력 박스의 값을 비우는 동작입니다. AMMR 내부 저장값은 [저장] 시점에 함께 비워집니다.
- 시스템에 단독 전달되지는 않습니다. 입력 박스 값 변경분은 [일괄 보고 재로드] 또는 다음 일괄 보고로 전달됩니다.

**일괄 보고 재로드 버튼:**

이 버튼은 AMMR이 6 Slot 전체의 slot_state + 입력된 식별값(있으면)을 시스템에 일괄 전달하는 동작을 Trigger합니다. 시스템은 받은 정보를 Core 확정 배정과 대조해 Slot별 Core 확정 Unit 정보·Job 배정을 일괄보고 응답(state/reconcile)으로 내려주며(재로드는 정합이 일치해도 응답이 옵니다), 이 응답으로 적재 상태 화면과 배정 상태 화면이 일괄 정정됩니다.

**이 영역 안내 문구 (화면에 함께 표시):**

> Slot별 입력 박스를 터치하면 가상 키보드가 표시되어 값을 직접 입력하실 수 있습니다. 향후 QR 리딩으로도 입력 가능합니다. Slot별 [초기화] 버튼을 누르면 해당 Slot 값이 비워집니다. [일괄 보고 재로드] 버튼을 누르시면 6 Slot 전체의 slot_state와 입력된 식별값이 시스템에 일괄 전달되어 사용 보류(blocked) 해소를 시도합니다. [편집] 버튼은 시스템 연결이 끊긴 상태에서만 활성화되고, 입력 박스와 [초기화] 버튼은 [편집]을 누른 뒤에만 열리며 [저장]으로 확정됩니다. [일괄 보고 재로드] 버튼은 시스템 연결이 유효하고 AMMR이 장애 상태가 아닐 때만 활성화됩니다. 이 화면 입력 값은 AMMR 재시작 후에도 유지되나, 재시작 시 Sensor가 미점유로 판별된 Slot은 저장값이 비워집니다. 자세한 동작은 이 문서 뒤쪽 적재 정보 재로드 동작 안내 부분을 참고해 주세요.

**활성화 조건:**

이 영역은 [편집]으로 열고 [저장]으로 닫으며, 시스템 전달은 [일괄 보고 재로드] 또는 다음 일괄 보고가 맡습니다.

- **[편집] 버튼**: 시스템 연결이 끊긴 상태에서만 활성화됩니다. 정상 운영 시에는 시스템이 적재 정보를 자동으로 채우므로 손입력이 오기입이 됩니다.
- **Slot별 입력 박스·[초기화] 버튼**: [편집]을 누른 뒤에만 활성화되고, [저장]을 누르면 다시 잠깁니다.
- **[일괄 보고 재로드] 버튼**: 시스템 연결이 유효하고 AMMR이 장애 상태가 아닐 때만 활성화됩니다. 시스템에 정보를 전달하는 동작이라 연결이 끊긴 동안에는 동작할 수 없습니다.

따라서 일반적인 사용 흐름은 다음과 같습니다 — 시스템 연결을 해제하고 [편집]을 누른 뒤 Slot 입력 박스에 Tray ID를 입력하고 [저장] → 시스템 재연결. 재연결 시점의 일괄 보고(초기 연결·시스템 연결 회복·주기 자동 발행)에 입력해 둔 값이 자동으로 실려 전달되므로 [일괄 보고 재로드]를 누르지 않아도 반영되며, [일괄 보고 재로드] 버튼은 이를 즉시 한 번 발행하는 동작입니다.

**미점유 Slot 값 비움 (Sensor 판별):** Sensor 판별에서 미점유(empty)로 나온 Slot은 그 Slot 관련 표시값 일체(적재 상태 화면 정보·배정 상태 화면 표시값·이 영역의 저장 입력값)를 비웁니다. 이 판별은 운영 중 Sensor 변화 시점과 AMMR 재시작(부팅) 시 Sensor 판별 시점 모두에 적용됩니다. 저장 입력값이 재시작 후에도 유지되는 것은 Sensor 판별에서 점유로 나온 Slot에 한하며, 그 값이 재연결 시 일괄 보고에 실리고, Core 확정 배정과 어긋나면 일괄보고 응답으로 정합됩니다.

## 7. Log 화면

AMMR에서 발생한 주요 Event를 시간순으로 보여주는 화면입니다. 이 화면의 Log는 AMMR이 자체적으로 기록한 것으로, 시스템 측은 이 화면에 개입하지 않습니다. 담당자가 현장에서 발생한 상황을 점검할 수 있도록 구성해 주시면 좋겠습니다.

**기록 분류:**

다음 3종 분류를 한 화면에 통합 시간순으로 표시해 주시면 좋겠습니다. 분류는 시스템과 주고받은 방향을 기준으로 나눴습니다. 분류 어휘는 문서 안내의 고정 항목이라, 본문에 적힌 그대로 적용해 주시기를 부탁드립니다.

- **시스템 → AMMR**: 시스템에서 받은 Event (작업 지시 수신, 일괄보고 응답 수신, 연결 상태 수신 등)
- **AMMR → 시스템**: 시스템으로 보낸 Event (일괄 보고 발행, 작업 결과 보고, 지시 수신 확인 발신, HW 상태 전이·Slot 적재 정보 변동 보고 등)
- **설정 변경**: 설정 화면에서 담당자가 변경한 항목 (임계치 변경, 접속 정보 변경 등)

**표시 컬럼:**

| 컬럼 | 내용                                                            |
|------|-----------------------------------------------------------------|
| 시간 | Event 발생 시각 (하단 안내 줄과 같은 메시지 timestamp 형식)     |
| 분류 | 위 3종 분류 중 하나 (시스템 → AMMR / AMMR → 시스템 / 설정 변경) |
| 내용 | Event 요약 문구                                                 |

**분류 필터:**

화면 상단에 분류 필터(전체 / 시스템 → AMMR / AMMR → 시스템 / 설정 변경)를 제공해 주시면 좋겠습니다. 선택된 분류에 해당하는 항목만 리스트에 표시됩니다. 필터 UI 형태(버튼·Dropdown·Toggle 등)는 업체 자유 결정 영역입니다.

**갱신 방식:**

이 화면의 모든 정보는 AMMR이 자체적으로 기록한 Event를 시간순으로 자동 표시합니다.

## 8. 적재 정보 재로드 동작 안내

이 장은 적재 정보가 시스템과 AMMR 사이에서 어떻게 흐르는지, 그리고 담당자가 수동으로 개입해야 하는 상황에서 [일괄 보고 재로드] 버튼이 어떻게 동작하는지를 정리했습니다.

**정상 운영 시 적재 정보 흐름:**

정상 운영(시스템 연결 유효 + AMMR Job 수행) 중에는 AMMR Slot의 적재 정보를 시스템이 자동으로 채워 줍니다. AMMR이 Pickup 또는 Dropoff 동작을 수행하면 Slot의 slot_state 변동이 시스템에 보고됩니다. Unit 정보(Unit 라벨·모델·버전·Tray 종류·단수·수량·용도)와 Job은 시스템이 Pickup/Dropoff 명령에 미리 담아 주므로 태블릿이 자체 채웁니다. 담당자가 설정 화면의 적재 정보 관리 영역에 별도로 개입할 필요는 없습니다.

**수동 입력이 필요한 상황:**

시스템 연결이 끊긴 상태에서 담당자가 현장에서 AMMR Slot의 Unit을 임의로 가져가거나 새로 올려놓는 상황이 발생할 수 있습니다. 시스템 측은 단절 동안 AMMR Slot의 변동을 인지하지 못합니다. 재연결 시 태블릿이 올리는 일괄 보고로 시스템이 적재 상태를 다시 맞추므로, 단절 동안 Slot을 손댔다면 그 값을 태블릿에 미리 채워 두어야 재연결 시 실물과 맞게 회복됩니다. 담당자는 시스템 연결이 끊긴 동안 사용 보류를 미리 풀어 두기 위해 설정 화면의 적재 정보 관리 영역에서 Slot별 입력 박스에 Tray ID를 직접 입력합니다. Tray ID 입력은 가상 키보드로 하며, 향후 QR 리딩(Tray QR 코드에 인코딩된 Tray ID를 스캐너로 읽어 입력)도 지원됩니다.

**[일괄 보고 재로드] 일괄 전달 동작:**

담당자가 [일괄 보고 재로드] 버튼을 누르면 AMMR은 6 Slot 전체의 slot_state + 입력된 식별값(있으면)을 시스템에 일괄 전달합니다. 시스템은 Core 확정 배정으로 확정한 Slot별 응답(state/reconcile)을 일괄 내려줍니다. 응답에는 Slot별 Core 확정 Unit 정보(Unit 라벨·모델·버전·Tray·수량·용도) + Job 배정 정보(출발·도착)가 포함되며, 이 응답으로 적재 상태 화면과 배정 상태 화면이 일괄 정정됩니다. 이 일괄 전달은 별도 재로드 전용 통신이 아니라 일괄 보고(초기 연결·시스템 연결 회복·주기 자동 발행과 같은 메시지)를 수동으로 한 번 발행하는 것이며, 발행 계기는 메시지의 `trigger` 값으로 구분되어 재로드는 `manual`로 실립니다. 끊긴 동안 입력해 둔 값은 재연결 시점의 일괄 보고에 자동으로 실리므로, [일괄 보고 재로드]를 누르지 않아도 반영됩니다.

**[일괄 보고 재로드]와 [최근 명령 재요청]의 구분:**

[일괄 보고 재로드]는 지금 Slot 상태와 보관 식별값을 시스템에 올려 사용 보류를 푸는 동작이고, [최근 명령 재요청]은 실패로 끝난 작업의 명령을 다시 내려 달라는 요청입니다. 앞엣것은 상태를 맞추는 일이고 뒤엣것은 작업 명령을 다시 받는 일이라 서로 다른 동작입니다. 다만 [최근 명령 재요청]을 누르면 태블릿이 같은 일괄 보고를 먼저 한 번 올리므로, 작업을 다시 지시받으려는 상황에서는 재로드를 먼저 누르지 않아도 됩니다. 재로드는 최근 명령 재요청과 상관없이 상태만 맞추고 싶을 때 쓰시면 됩니다.

**응답 없음 시 처리:**

[일괄 보고 재로드] 버튼을 누른 뒤 응답 대기 한도(초기값 3초) 안에 시스템 응답이 오지 않으면 실패로 판단해 하단 안내 줄에 띄우고, 담당자가 다시 시도하실 수 있습니다.

**버튼 활성화 조건:**

[일괄 보고 재로드] 버튼은 시스템 연결이 유효하고 AMMR이 장애 상태가 아닐 때만 활성화됩니다. 시스템 연결이 끊긴 상태에서는 비활성 표시됩니다 (시스템에 정보를 전달하는 동작이라 연결이 끊긴 동안에는 동작할 수 없습니다). 장애 상태에서도 비활성 표시됩니다. 장애 동안에는 시스템이 보고를 반영하지 않고, [Reset]으로 해제하면 자동으로 올라가는 보고로 적재 정보가 회복되기 때문입니다. 반대로 [편집] 버튼은 시스템 연결이 끊긴 상태에서만 활성화되며, Slot별 Unit 정보 입력 박스는 [편집]을 누른 뒤에만 열립니다 (정상 운영 시에는 시스템이 자동으로 채우므로 손입력이 오기입이 됩니다).

**응답 종류:**

시스템 응답은 Slot별로 다음 중 하나입니다.

- **정상 응답**: Core 확정 Unit 정보·Job 배정이 응답되어 화면에 표시됩니다.
- **빈 Slot 응답**: slot_state가 `empty`인 Slot은 빈 Slot으로 응답되어 적재 상태 화면의 정보 칸이 비어 있음으로 표시됩니다.
- **사용 보류(blocked) 응답**: 시스템이 입력된 식별값을 인지하지 못해 해당 Slot을 확정하지 못하면, 태블릿은 그 Slot을 `blocked`(사용 보류)로 표시합니다.

`blocked`(사용 보류)로 남은 Slot은 담당자가 입력 박스 값을 재확인하거나 Slot 실물을 확인하여 다시 [일괄 보고 재로드]를 시도할 수 있습니다. 태블릿 값으로 풀리지 않는 사유가 남아 있으면 재시도해도 사용 보류가 유지됩니다.

**AMMR 단절 중 Unit 바꿔치기:** 시스템 연결이 끊긴 동안 Slot의 Unit이 다른 Unit으로 교체되면, Sensor는 계속 점유로 잡혀 자동 감지되지 않습니다. 이 경우 담당자가 적재 정보 관리 영역에서 해당 Slot의 값을 새 Tray ID로 재입력(재맵핑)해야 합니다(현재 수동 입력, 향후 QR 리딩 지원). 재맵핑하지 않으면 옛 값이 그대로 보고되어 오배송이 발생할 수 있으며, 이때는 목적지 공정의 QR 확인 단계에서 불일치가 검출되어 처리됩니다. AMMR은 Slot의 Unit을 자체 인식하지 못해 자동으로는 회복되지 않습니다.

## 9. 참고용 UI 모형

아래 모형 5장은 참고용입니다. 어떤 정보가 어떤 영역에 배치되면 좋을지 보여드리기 위해 박스 구성과 Slot·표 배치를 시각화했습니다. 수동 조작 화면 모형은 버튼 그룹을 그렸고, 티칭·테스트 조작 그룹은 업체 자유 구현 영역이라 틀만 두었습니다. **실제 화면의 디자인·색상·폰트·세부 Component는 업체 자유 결정 영역**입니다.

각 모형은 외곽 박스 안에 네 영역(상단 고정 영역 / Sidebar / 표시 화면 / 하단 안내 줄)으로 분리해서 표시했습니다. 상단 고정 영역은 왼쪽에 운전 모드 버튼, 오른쪽 두 줄에 정보를 담았습니다. 실제 화면에서는 상단 고정 영역이 화면 상단에 고정되고, Sidebar가 화면 좌측에 고정되며, 표시 화면이 나머지 영역에, 하단 안내 줄이 화면 맨 아래에 배치됩니다. Sidebar의 `>` 표시는 현재 선택된 화면을 가리키는 표시 예시입니다.

화면 내용이 한 번에 다 안 보이면(특히 설정 화면) 표시 화면 안에서 스크롤로 보이는 방식이면 좋겠습니다.
